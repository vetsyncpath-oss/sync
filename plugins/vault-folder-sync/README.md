# Vault Folder Sync 0.4.0

Плагин Obsidian синхронизирует заметки и вложения с Google Drive, Яндекс Диском и папками WebDAV. Поддерживает получение файлов из публичных облачных папок и Git-репозиториев. У каждой пары папок своя история сравнения, направление обмена, правила конфликтов и расписание.

## Установка и обновление

1. Распакуйте каталог `vault-folder-sync` из установочного ZIP в `.obsidian/plugins/` своего хранилища. Если вы меняли каталог конфигурации Obsidian, используйте его вместо `.obsidian`.
2. При обновлении выключите плагин, замените `main.js` и `manifest.json` в его каталоге и включите снова. Сохраните существующий `data.json`. Адрес, папка, логин, интервал и история сравнения из версии 0.1.0 перенесутся в пару «Основная».
3. Откройте **Настройки → Сторонние плагины**, включите **Vault Folder Sync** и откройте его настройки. Выберите сервис и задайте удалённую папку. Локальная папка должна существовать. Пустой путь включает всё хранилище.
4. Нажмите **Предпросмотр** и проверьте список передач, пропусков и удалений. **Синхронизировать** повторно сравнивает актуальные файлы и выполняет обмен. Оба действия сохраняют настройки формы.

## Подключение сервиса

**Google Drive.** Укажите ID папки, ссылку на папку или `root` для корня «Моего диска». В настольном Obsidian кнопка **Подключить через JSON** открывает диалог. Выберите файл OAuth-клиента или вставьте JSON, затем нажмите **Открыть вход Google**. Если браузер не открылся, в диалоге можно открыть или скопировать ссылку. До завершения входа оставьте диалог открытым. Для этого в Google Cloud включите Google Drive API, настройте экран согласия OAuth и создайте учётные данные **OAuth client ID → Desktop app**. Если приложение находится в тестовом режиме, добавьте свой адрес в список тестовых пользователей. Скачайте JSON этого клиента и выберите его в плагине. Плагин запрашивает доступ к файлам Drive и идентификатор аккаунта, а затем обновляет токен автоматически. Google может ограничивать срок действия разрешения для тестового приложения.

Также можно ввести действующий OAuth access token с доступом `https://www.googleapis.com/auth/drive`. Этот способ доступен и на мобильном клиенте. Когда введённый вручную токен истечёт, понадобится новый. Документы Google Workspace и ярлыки пропускаются с записью в отчёт. Обычные файлы передаются вместе с содержимым. Совпадающие имена в одной папке Drive требуют устранения дубликата.

**Яндекс Диск.** Укажите существующую папку, например `disk:/Заметки`, и OAuth-токен Яндекс ID для Диска. При регистрации приложения предоставьте доступ к сведениям о Диске, чтению и записи файлов (права `cloud_api:disk.info`, `cloud_api:disk.read`, `cloud_api:disk.write`). Для хранилища целиком используйте `disk:/`. Плагин сверяет контрольную сумму до перезаписи и после загрузки. API Яндекс Диска допускает одновременную запись другим клиентом между проверкой и изменением файла.

**WebDAV.** Введите HTTPS-адрес существующей папки, логин и пароль приложения. Пример адреса Nextcloud — `https://cloud.example/remote.php/dav/files/alisa/Notes/`. При обновлении с 0.2.0 каждая существующая пара сохраняет WebDAV, свои политики, расписание и историю.

**Данные входа.** Пароль и токены сеанса хранятся в памяти. Для автозапуска после перезапуска можно включить **Сохранить введённый токен в связке ключей Obsidian** и сохранить пару. Для Google при входе через браузер в связку ключей помещаются данные для обновления токена. При смене провайдера или облачного аккаунта плагин заново сравнивает файлы.

## Получение из публичных источников

| Сервис в настройках | Что указать |
| --- | --- |
| Google Drive · публичная папка | Ссылку на папку с доступом для всех по ссылке или её ID и **API key** проекта с включённым Drive API. Если ссылка содержит resourcekey, вставьте её полностью. Для этого режима OAuth-клиент не нужен. |
| Яндекс Диск · публичная папка | Публичную ссылку владельца, например `https://disk.yandex.ru/d/…`. Токен не требуется. Плагин обходит страницы каталога и вложенные папки. |
| Git · публичный репозиторий | HTTPS URL клонирования, например `https://github.com/owner/repo.git`. Отдельно можно выбрать ветку, тег, SHA коммита и путь внутри репозитория. Пустые поля означают HEAD и корень. |

Все три режима записывают файлы только в Obsidian. Для уже изменённой локальной заметки действует выбранная политика конфликтов. Если явно включена передача удалений, исчезновение ранее синхронизированного файла перемещает неизменённую локальную копию в корзину после повторной проверки источника.

GitHub использует анонимный REST API с лимитом запросов. Другие публичные HTTPS Git-серверы, в том числе GitLab, поддерживаются на компьютере с Git в PATH. Временный bare-репозиторий удаляется после запуска. Символьные ссылки, submodules и Git LFS требуют отдельной обработки и останавливают запуск при попадании в выбранную папку. Для системного Git максимальный вывод одной команды — 64 МиБ, включая отдельный файл. Системные настройки авторизации Git для этого публичного режима не используются.

## Пары и режимы работы

В основном режиме доступны подключение, локальная папка, направление и таймер. Расширенный режим открывает политики удаления, конфликтов и дополнительные события автозапуска. Переключение вида сохраняет выбранные политики. Перед выбором другой пары сохраните форму. Удаление пары убирает её настройки и историю сравнения, файлы остаются в папках.

| Направление | Действие |
| --- | --- |
| В обе стороны | Обновления могут приходить с любой стороны. |
| Из Obsidian в сервис | Изменения вносятся в удалённую папку. Правки файла на стороне назначения рассматриваются как конфликт. |
| Из сервиса в Obsidian | Изменения вносятся в Obsidian. Правки файла на стороне назначения рассматриваются как конфликт. |

Ручные команды и кнопка на ленте запускают выбранную пару. Отчёт доступен через палитру команд до отключения плагина. Автоматические запуски разных пар выполняются последовательно.

## Политики удаления

Удаление распознаётся по последней общей версии файла. При первом обмене файл на одной стороне считается новым. В одностороннем режиме новый файл, найденный только на стороне назначения, остаётся там.

| Политика | Что произойдёт |
| --- | --- |
| Восстанавливать копию (по умолчанию) | Оставшийся файл копируется обратно, если это допускает направление. |
| Оставлять удалённым | Исчезновение ранее синхронизированного файла пропускается. Плагин сохраняет историю пары. |
| Передавать удаление | Исчезновение из источника удаляет прежнюю копию в назначении. В двустороннем режиме это работает в обоих направлениях. В одностороннем режиме удаление только в назначении восстанавливается из источника. |

При передаче удаления локальный файл перемещается в корзину хранилища. Google Drive и Яндекс Диск перемещают файлы в свою корзину. Для WebDAV отправляется условный запрос DELETE. Возможность восстановления удалённой копии зависит от сервера. Если оставшийся файл изменился, плагин выводит конфликт и сохраняет его. Переименование рассматривается как появление нового пути и исчезновение старого.

## Конфликты

Когда обе копии изменились или уже различаются при первом сравнении, можно выбрать пропуск с отчётом (по умолчанию), локальную версию, удалённую версию или более новую версию. При выборе по времени сравниваются часы устройства и время изменения по данным сервиса с точностью до секунды. Если время отсутствует или совпадает, конфликт остаётся в отчёте. Решение, которое потребовало бы записи против выбранного направления, также пропускается.

Строгий ETag нужен для замены или удаления существующего файла на WebDAV. Если сервер не дал ETag, плагин сообщает об этом в отчёте. Если версия успела измениться во время операции, обмен останавливается. Повторный запуск сравнит актуальное состояние.

## Автосинхронизация

Для каждой пары можно совместить несколько условий запуска.

- При открытии хранилища, после загрузки списка файлов.
- По таймеру с интервалом 5, 15, 30 минут, 1 час, 6 или 24 часа.
- После локальной правки, создания, перемещения или удаления. Пауза в 5, 15, 30 или 60 секунд отсчитывается от последнего события.
- При восстановлении сети по событию системы.

По умолчанию автозапуск выключен. Настройки пары и отсутствие сети приостанавливают очередь. Пароль сеанса хранится в памяти. Для автоматического запуска после перезапуска в версиях Obsidian с хранилищем секретов можно указать имя существующего секрета с паролем. При использовании пароля сеанса введите его, сохраните пару и закройте настройки.

## Совместимость

Плагину нужен Obsidian 1.6 или новее. Для пар WebDAV сервер должен поддерживать PROPFIND, GET, PUT, MKCOL и, для передачи удалений, DELETE. Фоновая работа зависит от того, позволяет ли система Obsidian выполнять код. Скрытые пути, каталог конфигурации и пустые папки пропускаются. Вложения обрабатываются по одному и целиком в памяти.
