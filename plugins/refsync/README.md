# Sync Studio 0.8.2

## Первое подключение Vault Access Manager

Для всех профилей, включая локальные пары, Sync Studio автоматически проверяет разрешение персонализированного Vault Access Manager с SDK 6 в текущем хранилище. Включите Manager и войдите через **Открыть вход VAM**. Синхронизация доступна, когда Manager подтверждает право использования для текущей организации, бандла и устройства. Привязывать Manager для этого не требуется.

В разделе **Отчёты и обновления** можно отдельно разрешить Manager запрашивать сводку и передавать сигналы о версиях VAM и Sync Studio. Привязка действует на этом устройстве для выбранного хранилища, организации и бандла. В версии 0.8.1 этот обмен выключен по умолчанию, в том числе после обновления с 0.8.0. Отключение привязки сразу прекращает обмен. Право синхронизации по-прежнему определяет Manager.

В Manager 0.8.0-alpha.5 откройте настройки VAM и разверните **Диагностика Sync Studio**. При включённой привязке панель показывает допуск, текущую операцию, потребность в восстановлении и последние 32 события применения профилей. Время попытки относится к началу применения, время успеха — к последнему полностью завершённому применению. Неполное применение указывается отдельно. Сводка существует в памяти до перезапуска Sync Studio или изменения привязки. В неё входят только события за время привязки. В панели нет имён профилей, путей, адресов источников и текстов ошибок. Полный журнал доступен в Sync Studio. Отчёт читается локально.

Диспетчер вызывает методы экземпляра `refsync`, передавая свой экземпляр Manager первым аргументом. `getDispatchStatus(manager)` возвращает `null` без действующей привязки. Сводка протокола 1 сохраняет поля `version`, `access` и `phase` версии 0.8.1 и добавляет `pluginId`, `gate`, `running`, `recoveryPending`, `failedProfiles`, временные метки, код последней ошибки и массив `events`. `subscribeDiagnostics(manager, notify)` возвращает функцию отписки или `null`. Уведомление предлагает перечитать сводку. `receiveUpdateSignal(manager, {protocol: 1, component, version})` принимает идентификаторы `vault-access-manager` и `refsync`. Полученные версии видны в настройках до перезапуска или отключения привязки.

Настройки и история доступны при заблокированном доступе. Для просмотра удалённых файлов, проверки записи, запуска, подтверждения плана и ручного отката требуется действующий допуск. Срок офлайн-доступа определяет Manager. При отзыве новые операции останавливаются. Отправленный сетевой запрос может завершиться; журнал сохраняет сведения для восстановления. Восстановление на облачной стороне продолжится после получения допуска. Истечение срока или отзыв отображаются в строке состояния без регулярных всплывающих уведомлений.

Sync Studio доставляет файлы источника в одну сторону. Профиль подписчика читает источник и обновляет локальную папку. Издатель публикует в обратном направлении. Для двух папок одного хранилища доступны обе роли. Публичные папки Google Диска, Яндекс Диска и репозитории Git по HTTPS доступны подписчику.


При публикации крупного файла в Google Drive плагин запоминает сессию отправки на этом устройстве. После обрыва повторный запуск профиля запрашивает подтверждённую позицию у Drive. Изменение содержимого, назначения или истечение срока сессии приводит к новой отправке. На настольном Obsidian первичная публикация обычного файла контента размером больше 8 МиБ читает источник, записывает промежуточную копию и отправляет её частями. Для замены существующего файла требуется дополнительное место под резервную копию. Загрузка с Drive при получении всё ещё формирует полный буфер файла.

## Установка и обновление с предыдущих версий

Для Obsidian 1.8.7 или новее. Отключите Sync Studio на время обновления. Распакуйте установочный ZIP **поверх** каталога `<действующая папка настроек>/plugins/`. При стандартной конфигурации файл плагина окажется в `.obsidian/plugins/refsync/main.js`. Включите Sync Studio в списке сторонних плагинов.

На Windows в Проводнике включите показ скрытых элементов. Откройте папку хранилища и скопируйте из ZIP папку `refsync` в `.obsidian\plugins\` (либо в `plugins` вашего каталога конфигурации). В самом редакторе профиля указывайте пути относительно хранилища, например `Папки\Источник`.

При обновлении сохраните имеющиеся `refsync/data.json` и `refsync/runtime/`. Архив содержит только файлы поставки. При первом открытии новой версии прочитает профиль M1, сохранит его ID, папки и ручной режим запуска. Существующие резервные копии остаются доступны для отката. При сохранении настроек профиль записывается в новый формат списка.

## Настройка состава и диагностика

В списке профилей видны направление, охват, политика удаления и расписание. Откройте профиль и выберите раздел редактора.

- **Расположения и направление.** Обзор работает для обеих локальных папок, а также для папки подключения в облаке и Git. Локальные пути отсчитываются от корня открытого vault. Для всего хранилища выберите `/`. На странице **Расположения** можно создать, проверить и изменить именованный путь. Профиль сохраняет связь при выборе расположения из списка. Пользовательский путь отсоединяет эту сторону. Изменение общей папки показывает затронутые профили перед сохранением.
- **Состав.** Вариант **Только выбранное** начинает с пустого охвата. Отметьте папку, чтобы включить её будущие файлы, или отметьте отдельные файлы, включая файлы в корне. Для старых профилей сохраняется режим **Всё, кроме исключений**. Маски и предел размера действуют в обоих режимах. Добавление папки конфигурации в «Контент» передаёт файлы; охват «Настройки» поддерживает категории, локальные поля JSON и перезагрузку. В списке плагинов этого охвата отдельно выбираются код, данные и дополнительные файлы.
- **Правила.** Выберите добавление и обновление без удалений, передачу удалений ранее доставленных объектов или полное зеркало. В сводке рядом с правилом показана папка назначения. Служебные пути, собственная папка Sync Studio и пути за пределами выбранного охвата защищены.
- **Запуск.** Здесь задаются режим и триггеры. Для профилей настроек доступны запуск при открытии и интервал. Обновление отключает старые невидимые триггеры фокуса, сети и событий файлов в этих профилях.
- **Диагностика.** Проверьте относительный путь или откройте **Просмотр изменений**, чтобы увидеть результат для несохранённого черновика. Команда создания недостающих папок отдельно перечисляет пути перед их созданием. Тихая синхронизация запускается по сохранённым параметрам.
- **Шаблоны.** В главном окне доступны сценарии для заметок, публикации, зеркала, оформления, данных плагинов и ручного запуска. Шаблон всей задачи выбирается в разделе расположений. В разделе «Состав» можно сохранить и применить шаблон состава. Пользовательские маски включения и исключения открываются при выборе своего набора типов файлов. Экспорт и импорт используют JSON. Папки, авторизация, ID облачных аккаунтов и состояние доставки в шаблон не входят. Профиль из шаблона создаётся выключенным.

**Журнал операций** доступен из настроек, меню значка и палитры команд. В нём есть время, профиль, записанные и удалённые файлы, созданные и удалённые папки, причины отсрочек и ошибки. Поиск работает по профилю, операции и пути. Для старых запусков доступны сохранившиеся сводки. Журнал ограничен двумя ротируемыми файлами примерно по 2 МиБ. В тихом режиме список и журнал открываются по запросу.

При сравнении строка состояния показывает количество просмотренных папок и файлов, чтений и результатов, полученных из метаданных. На настольной системе ключ кэша учитывает путь, идентификатор файла, размер, время изменения содержимого и метаданных файловой системы. Базовая линия и кэш хранятся на устройстве в IndexedDB. Старое состояние переносится при следующей успешной записи. Google Диск и Яндекс Диск могут отдавать SHA-256 в списке файлов. Для источников без надёжной версии содержимое читается заново. Перед записью плагин сверяет байты источника. Команда **Диагностика · полная проверка файлов** обходит кэш и сохраняет результаты проверки в журнале. У больших зеркал сохраняются тайм-ауты отдельных операций, а общее время работы зависит от объёма и скорости обеих сторон.

## Папки и обновление с RefSync

Это обновление RefSync. В списке плагинов и в командах отображается **Sync Studio**. Внутри ZIP остаётся каталог `refsync`: распакуйте его поверх прежнего каталога в `.obsidian/plugins/` или в `plugins` действующей папки конфигурации. Идентификатор установки, привязка аккаунтов и журнал отката сохранены.

- Недостающие каталоги создаются от родительских к вложенным. Пустые папки из источника тоже передаются, если входят в охват профиля. Git обычно хранит только каталоги с отслеживаемыми файлами.
- В **полном зеркале** просмотр изменений показывает лишние каталоги, в том числе пустые папки, оставшиеся после прежних запусков. Файлы удаляются первыми, папки — от самых глубоких к родительским. Корень профиля сохраняется.
- В **зеркале с сохранением** при включённых удалениях очищаются папки, которые плагин создал или в которые доставил файлы. Для состояния старого формата учитываются также пути родителей ранее доставленных файлов. Пустые локальные папки без истории доставки сохраняются.
- Перед удалением плагин проверяет оставшееся содержимое. Исключённый файл, скрытый элемент или оставшаяся подпапка сохраняют каталог. Пустые каталоги участвуют в защите от массовых удалений, выборе строк плана, журнале и откате. При откате создания папка с появившимся в ней локальным файлом сохраняется.
- Для удаления папок в Google Диске подключите аккаунт с областью **Доступ ко всему Диску**. С `drive.file` API может скрыть содержимое папки, поэтому очистка останавливается на каталоге. Google Диск и Яндекс Диск отправляют каталог в корзину после повторного листинга. При работе нескольких издателей учитывайте промежуток между ответом API и удалением.

## WebDAV на Windows и других настольных системах

В редакторе профиля откройте «Расположения и направление», выберите WebDAV и укажите HTTPS-адрес коллекции. Скопируйте его из настроек WebDAV вашего сервера. Укажите имя пользователя и пароль приложения, затем нажмите «Сохранить пароль». Пароль привязан к адресу, пользователю и этому устройству. Для общедоступной коллекции оставьте пользователя пустым. HTTP поддерживается только для локального сервера на компьютере. Путь профиля отсчитывается от указанной коллекции.

В диагностике «Проверить доступ» проверяет список объектов. «Проверить запись временным файлом» создаёт отдельный файл, читает, заменяет и удаляет его. Результат показывает выполненные операции и имя файла, если его очистку не удалось подтвердить. Обе проверки запускаются вручную из настроек.

Издатель отправляет файлы обычным WebDAV PUT и проверяет SHA-256 повторным чтением с сервера. Для замены и удаления файлов требуется сильный ETag. Для удаления пустой папки сервер должен поддерживать исключительную блокировку всего её дерева. Без такой блокировки пустая папка остаётся на сервере. После обрыва WebDAV начинает передачу файла заново. В строке состояния виден объём передачи крупных файлов с известным размером, а результат доступен в журнале.

## Подключение личного облачного аккаунта

В **Настройки → Sync Studio → Аккаунты** выберите сервис и нажмите **Подключить аккаунт**. Один аккаунт можно использовать в нескольких профилях. На каждом устройстве войдите отдельно. При отзыве refresh-токена автоматические запуски профилей этого аккаунта приостанавливаются. В разделе **Аккаунты** видны статус и названия связанных профилей. Для восстановления нажмите **Войти через браузер** и выберите ту же учётную запись, OAuth-клиент и область доступа.

### Google Диск на Windows

1. Создайте проект в Google Cloud Console, включите **Google Drive API**, настройте экран согласия и добавьте свою почту в тестовые пользователи, если приложение находится в режиме тестирования.
2. Создайте **OAuth client ID → Desktop app**, скачайте JSON. В окне подключения Google выберите файл или вставьте содержимое в поле JSON. После успешного импорта появится сообщение «JSON-клиент загружен».
3. Для Desktop app оставьте поле адреса возврата пустым. Нажмите **Войти через браузер**. Sync Studio открывает системный браузер, выбирает свободный локальный порт и принимает ответ по `http://127.0.0.1:<порт>/`. После согласия вернитесь в Obsidian.
4. По умолчанию используется область `https://www.googleapis.com/auth/drive.file`. Google показывает файлы и папки, предоставленные этому OAuth-приложению. Для чтения существующего произвольного дерева явно включите **Доступ ко всему Диску** и подтвердите область `https://www.googleapis.com/auth/drive`.
5. Для мобильного клиента или ручного HTTPS-возврата создайте клиент типа **Web application**, зарегистрируйте свой точный HTTPS redirect URI и импортируйте его JSON. Используйте страницу под своим контролем. После входа скопируйте полный адрес возврата в поле Sync Studio и нажмите **Завершить вход**. Sync Studio проверяет `state`, а код обменивает с PKCE S256. Окно также принимает код, вручную скопированный в пределах текущей попытки входа.

[Настройка настольного OAuth-клиента Google](https://developers.google.com/identity/protocols/oauth2/native-app) · [Области доступа Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

### Яндекс Диск

1. Зарегистрируйте приложение в Яндекс OAuth. Для рабочего каталога приложения выберите права `cloud_api:disk.app_folder` и `cloud_api:disk.info`. Для доступа к другим каталогам зарегистрируйте `cloud_api:disk.read`, `cloud_api:disk.write` и `cloud_api:disk.info`.
2. Настройте адрес возврата. В Sync Studio по умолчанию указан `obsidian://refsync-oauth`. Если для вашей платформы в консоли доступен HTTPS redirect URI, зарегистрируйте собственный HTTPS-адрес и укажите его в Sync Studio. Оба значения должны совпадать.
3. Введите Client ID и, если требуется для вашего клиента, Client secret. Выберите ту же область доступа, что в консоли. Нажмите **Войти через браузер**. При ручном возврате вставьте код или полный URL из браузера и нажмите **Завершить вход**.
4. В режиме папки приложения пути считаются от `app:/`. При полном доступе они считаются от `disk:/`. Ссылки, выданные Яндексом для загрузки и скачивания, используются отдельно от авторизованных запросов к файловому API.

[Регистрация приложения Яндекса](https://oauth.yandex.ru/) · [API Яндекс Диска](https://yandex.com/dev/disk/)

### Публикация и подписка

В профиле выберите **Google Диск · OAuth** или **Яндекс Диск · OAuth**, подключённый аккаунт и роль. Для Google можно задать ID или ссылку на базовую папку. **Обзор папок источника** позволяет выбрать подкаталог. Путь в поле ниже задаётся относительно выбранного корня. Издатель может создать его кнопкой **Создать недостающие папки**. Для первой публикации удобно выделить отдельную папку на каждый охват.

- **Издатель** отправляет локальные заметки или выбранные файлы действующей папки настроек Obsidian в облако. Профиль использует обычные правила зеркала, фильтры и настройки тихих удалений. Google получает файлы через resumable upload, Яндекс выдаёт URL для загрузки. Удаления на стороне облака используют корзину сервиса. Локальный журнал Sync Studio хранит резервные копии для отката.
- **Подписчик** получает дерево из облака. После публикации в корне лежит `.sync-manifest.json` с ревизией, датой, ID устройства издателя, путями, размерами и SHA-256. При записи издатель сначала ставит отметку о незавершённой публикации, затем загружает файлы и последним записывает полный манифест. При остановке между этими шагами подписчик прерывает применение. Для папки без манифеста используется листинг. При выборе вложенного каталога манифест ищется в выбранном корне.
- Охват подписчика может быть уже опубликованного. При расхождении манифеста и выбранных файлов просмотр изменений сообщит об ошибке. Для независимых издателей используйте разные каталоги. Сериализация запусков действует внутри одного экземпляра Sync Studio; распределённой блокировки между компьютерами у облачных API в этой версии нет.
- Аккаунт привязан к идентификатору пользователя сервиса, OAuth-клиенту и области доступа. Токены и client secret сохраняются в SecretStorage Obsidian, а в версиях до 1.11.4 — в локальном хранилище устройства. В `data.json` профиля записываются идентификатор подключения и местоположение папки. Для восстановления прерванной публикации или отката нужен доступ к тому же аккаунту. Если файл успели изменить в облаке, восстановление останавливается на расхождении. Сохраните стороннюю правку отдельно, восстановите опубликованную или исходную версию файла и повторите запуск профиля.
- Вход и refresh используют учётные данные вашего приложения. При ограничениях провайдера проверьте права, тестовых пользователей, redirect URI и доступ выбранного аккаунта к нужной папке. Тесты в поставке используют синтетические ответы сервисов. В CI на Windows реальный Obsidian открывает диалог выбора JSON, принимает локальный OAuth-возврат и проверяет публикацию, подписку и откат на тестовом Drive.

## Подключение публичного источника

В **Настройки → Sync Studio → Добавить** выберите подключение. Укажите локальную папку для заметок или выберите охват **Настройки** для доставки в действующую папку конфигурации Obsidian.

| Источник | Что ввести |
| --- | --- |
| Google Диск | Включите Google Drive API в своём проекте Google Cloud, создайте API-ключ с ограничением по API на Google Drive API и сохраните его в поле для этого устройства. Вставьте ссылку на папку с доступом «Все, у кого есть ссылка» или её ID. При наличии `resourcekey` используйте полную ссылку. |
| Яндекс Диск | Опубликуйте папку и вставьте ссылку вида `https://disk.yandex.ru/d/…` или публичный ключ API. Для чтения опубликованной папки достаточно этой ссылки. |
| Git | Скопируйте HTTPS-адрес клонирования публичного репозитория. Можно указать ветку, например `main`, или оставить поле пустым для ветки по умолчанию. Понадобится сервер с поддержкой Git smart HTTP и shallow fetch. |

Нажмите **Обзор папок источника**, откройте вложенную папку и нажмите **Выбрать эту папку**. Можно также ввести путь вручную. Для настроек выберите каталог, непосредственно содержащий `app.json`, `themes/` и другие нужные файлы, например `.obsidian` в Git. Создайте локальную папку кнопкой в редакторе, включите профиль, сохраните и откройте **Просмотр изменений**.

API-ключ Google хранится в локальном хранилище Obsidian для этого устройства. Публичная ссылка сохраняется в профиле. Сбой листинга или неоднозначные имена останавливают доставку. Перед локальным удалением из облачного зеркала Sync Studio повторно читает соответствующие каталоги. Google Docs, Sheets, ярлыки, символические ссылки Git и подмодули пропускаются. Git LFS доставляется как файл-указатель.

Подписка Git читает дерево одного коммита. Его дата служит временем изменения для политики «Предпочесть более новый». После shallow fetch объекты остаются в `<configDir>/plugins/refsync/runtime/git/`. На мобильном устройстве учитывайте размер всего снимка ветки, даже если для доставки выбрана одна подпапка.

## Первая доставка

1. Откройте **Настройки → Sync Studio**. Отредактируйте существующий профиль или добавьте новый. Новый профиль и дубликат изначально выключены. Введите имя, оставьте роль «Подписчик», выберите охват «Контент» и две отдельные папки. Кнопка «Создать недостающие папки» создаст их. Включите профиль и сохраните.
2. Поместите заметку в папку источника. «Просмотр изменений» показывает предстоящие действия. В режиме «План с подтверждением» кнопка «Синхронизировать» открывает план, где можно исключить строки, посмотреть текстовые различия, выбрать действие по конфликту и скопировать план в JSON. Нажмите «Применить выбранное». Снятая галочка пропускает путь в текущем проходе.
3. Для автосинхронизации выберите «Тихий» и нужные триггеры. Доступны старт с задержкой, интервал, фокус окна, появление сети и изменения файлов. Интервал у новых профилей — пять минут. Нулевой интервал оставляет остальные выбранные триггеры. Обработка работает, пока Obsidian открыт и ОС разрешает приложению выполнение.
4. В списке профилей доступны дублирование, изменение порядка, выбор текущего, запуск одного или всех активных профилей и общая пауза. Команда «Откатить последнюю доставку» восстанавливает прежние байты и убирает созданные файлы текущего профиля. Откат заменяет последующие правки этих файлов.

## Политики контента

| Параметр | Поведение |
| --- | --- |
| Зеркало с сохранением | Сохраняет локальные файлы. При включённой передаче удалений в корзину попадают только ранее доставленные файлы, исчезнувшие из источника. |
| Полное зеркало | Возвращает файлы к версии источника и удаляет лишние файлы внутри фильтров. Защита удерживает удаления при пустом или резко уменьшившемся источнике и при превышении заданных порогов. Команда «Разрешить выбранные отложенные удаления» открывает отдельный список для подтверждения по путям. |
| Защита от массовых удалений в тихом режиме | По умолчанию включена и при обновлении, и для новых профилей. Выключите её в редакторе профиля, чтобы тихая доставка выполняла все удаления по правилам зеркала при любом количестве и проценте, в том числе при пустом или резко уменьшившемся источнике. Это действует и при наследовании тихого режима. Просмотр изменений показывает эффект следующего запуска. При просмотре перед первой доставкой действуют обычные пороги. |
| Конфликты | Предпочесть источник, предпочесть цель, предпочесть более новый файл (допуск часов 2 секунды) или сохранить обе версии. Локальная копия получает суффикс с ID устройства и временем. |
| Удаления | Корзина Sync Studio с заданным сроком хранения, корзина хранилища, системная корзина при поддержке ОС или удаление после бэкапа. Корзина Sync Studio находится в `<configDir>/plugins/refsync/runtime/trash/`. Очистка просроченных записей выполняется при работе плагина. |
| Фильтры | Include/exclude glob через запятую, например `**/*.md,**/*.png`. Ограничение размера задаётся в МиБ и учитывает обе стороны. Исключённый путь защищён от удаления. |
| Открытые файлы | Недавняя правка в редакторе откладывает доставку затронутого файла. После заданного числа отсрочек применяется политика профиля с бэкапом. Издатель перед записью сверяет размер и время изменения источника с интервалом не менее двух секунд. |
| Сбои | Переходные блокировки повторяются с задержкой; занятый файл по возможности откладывается, другие файлы продолжают обработку. Если запись превысила тайм-аут, журнал сохраняется, а новые записи ждут завершения предыдущей операции и восстановления. |

## Папка настроек Obsidian

В профиле выберите охват «Настройки». Локальной стороной станет действующая папка конфигурации, которую Obsidian сообщает через `app.vault.configDir`. В источнике храните её **содержимое**. Например, `snippets/example.css` будет доставлен в `<configDir>/snippets/example.css`.

1. В редакторе профиля выберите пресет или включите нужные категории. Доступны корневые JSON, оформление, темы, сниппеты, список community-плагинов, код, данные и прочие файлы плагинов. Для кода и данных имеются раздельные разрешающие и исключающие списки ID. В старом профиле M1/M2 сохраняются прежние категории и ручной запуск. Полную доставку кода включайте явно для источника, которому доверяете: Obsidian исполняет доставленный JavaScript при загрузке соответствующего плагина.
2. Чтобы сохранить локальные поля JSON, укажите по одному правилу на строку. Например, `plugins/*/data.json => accounts[*].token` сохраняет токены учётных записей цели. Поддержаны ключи через точку, числовые индексы и wildcard. Для сравнения игнорируются порядок ключей, пробелы и UTF-8 BOM. Бэкап содержит прежние байты файла, включая локальные значения.
3. Выберите пакетное применение или только изменения. В пакетном режиме сначала проверяются и готовятся файлы плана. Ошибка чтения или записи возвращает исходное состояние. Очерёдность доставки — код и ресурсы, данные плагинов, корневые настройки, затем список включённых плагинов. При замене `data.json` Sync Studio временно выгружает ранее активный плагин и загружает его после записи, если Obsidian предоставляет соответствующие методы.
4. Перезагрузку можно выполнить сразу, при простое, отложить до следующего запуска или оставить отметку в строке состояния. Автоперезагрузки ограничены двумя за час с интервалом минимум пять минут. При следующей загрузке Sync Studio сверяет доставленные файлы с сохранённым пакетом и записывает расхождения в журнал. Локальные правки сохраняются. Повторную доставку определяет политика профиля.
5. Команда отката возвращает прежние файлы из журнала. При доставке списка включённых плагинов Sync Studio сохраняет в нём свой ID. Чтобы снять остальные включения, поместите в источник список `[]`. Собственная папка Sync Studio, раскладка окон, кэш и служебные каталоги защищены. На мобильных устройствах фильтр пропускает плагины с `isDesktopOnly` и исключает их ID из доставляемого списка.

**Windows.** Имена устройств (`CON`, `LPT1` и другие), двоеточия, конечные точки/пробелы и коллизии регистра или нормализации Unicode отмечаются в плане. Проблемные пути защищены также от удаления в полном зеркале. Занятые файлы повторно обрабатываются с задержкой. Windows CI собирает плагин, запускает тесты и открывает установочный ZIP в отдельном хранилище настоящего Obsidian.

## Ограничения

- Публикация в Git запланирована на M6.
- Профили настроек поддерживают ручной запуск, старт и интервал. Изменения рабочих раскладок не доставляются в работающее приложение. Для плагинов доступны галочки и маски ID, для локальных полей JSON — текстовые правила. Настройка применяется к существующим и новым файлам в пределах выбранного охвата.
- Первый локальный обход читает содержимое файлов для SHA-256. Последующие сравнения контента используют сохранённые контрольные суммы, когда метаданные подтверждают ту же версию. Большие планы выводятся страницами по 50 строк. Текстовый diff ограничен 128 КиБ; для больших и бинарных файлов отображаются метаданные. Просмотр изменений показывает создание и удаление каталогов отдельными строками. Одновременные профили обслуживаются последовательно.
- Корзина Sync Studio и журнал отката хранят разные копии. После проверки настроек удаляется временная копия пакета. Очистка журнала раз в сутки оставляет последнюю доступную доставку для отката и транзакции с незавершённым восстановлением или проверкой. Резервные копии отката хранятся отдельно от корзины.
- Физические iOS/Android и системная корзина других ОС не входят в настольную проверку этой сборки.
