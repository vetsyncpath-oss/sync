# RefSync 0.2.0 · M2

RefSync доставляет файлы эталона в одну сторону. Профиль подписчика читает эталон и обновляет локальную папку. Издатель публикует в обратном направлении. В M2 обе папки находятся в одном хранилище Obsidian. Начните с двух непересекающихся тестовых папок.

## Установка и обновление с M1

Для Obsidian 1.8.7 или новее. Отключите RefSync на время обновления. Распакуйте установочный ZIP **поверх** каталога `<действующая папка настроек>/plugins/`. При стандартной конфигурации файл плагина окажется в `.obsidian/plugins/refsync/main.js`. Включите RefSync в списке сторонних плагинов.

При обновлении сохраните имеющиеся `refsync/data.json` и `refsync/runtime/`. Архив содержит только файлы поставки. При первом открытии M2 прочитает профиль M1, сохранит его ID, папки и ручной режим запуска. Существующие резервные копии остаются доступны для отката. При сохранении настроек профиль записывается в новый формат списка.

## Первая доставка

1. Откройте **Настройки → RefSync**. Отредактируйте существующий профиль или добавьте новый. Новый профиль и дубликат изначально выключены. Введите имя, оставьте роль «Подписчик», выберите охват «Контент» и две отдельные папки. Кнопка «Создать недостающие папки» создаст их. Включите профиль и сохраните.
2. Поместите заметку в папку эталона. «Пробный план» показывает предстоящие действия. В режиме «План с подтверждением» кнопка «Применить эталон» открывает план, где можно исключить строки, посмотреть текстовые различия, выбрать действие по конфликту и скопировать план в JSON. Нажмите «Применить выбранное». Снятая галочка пропускает путь в текущем проходе.
3. Для автосинхронизации выберите «Тихий» и нужные триггеры. Доступны старт с задержкой, интервал, фокус окна, появление сети и изменения файлов. Интервал у новых профилей — пять минут. Нулевой интервал оставляет остальные выбранные триггеры. Обработка работает, пока Obsidian открыт и ОС разрешает приложению выполнение.
4. В списке профилей доступны дублирование, изменение порядка, выбор текущего, запуск одного или всех активных профилей и общая пауза. Команда «Откатить последнюю доставку» восстанавливает прежние байты и убирает созданные файлы текущего профиля. Откат заменяет последующие правки этих файлов.

## Политики контента

| Параметр | Поведение |
| --- | --- |
| Зеркало с сохранением | Сохраняет локальные файлы. При включённой передаче удалений в корзину попадают только ранее доставленные файлы, исчезнувшие из эталона. |
| Полное зеркало | Возвращает файлы к версии эталона и удаляет лишние файлы внутри фильтров. Защита удерживает удаления при пустом или резко уменьшившемся эталоне и при превышении заданных порогов. Команда «Разрешить выбранные отложенные удаления» открывает отдельный список для подтверждения по путям. |
| Конфликты | Предпочесть эталон, предпочесть цель, предпочесть более новый файл (допуск часов 2 секунды) или сохранить обе версии. Локальная копия получает суффикс с ID устройства и временем. |
| Удаления | Корзина RefSync с заданным сроком хранения, корзина хранилища, системная корзина при поддержке ОС или удаление после бэкапа. Корзина RefSync находится в `<configDir>/plugins/refsync/runtime/trash/`. Очистка просроченных записей выполняется при работе плагина. |
| Фильтры | Include/exclude glob через запятую, например `**/*.md,**/*.png`. Ограничение размера задаётся в МиБ и учитывает обе стороны. Исключённый путь защищён от удаления. |
| Открытые файлы | Недавняя правка в редакторе откладывает доставку затронутого файла. После заданного числа отсрочек применяется политика профиля с бэкапом. Издатель перед записью сверяет размер и время изменения источника с интервалом не менее двух секунд. |
| Сбои | Переходные блокировки повторяются с задержкой; занятый файл по возможности откладывается, другие файлы продолжают обработку. Если запись превысила тайм-аут, журнал сохраняется, а новые записи ждут завершения предыдущей операции и восстановления. |

## Папка настроек Obsidian

Охват «Настройки» использует `app.vault.configDir`, в том числе при переименовании стандартной папки. Поместите, например, `snippets/example.css` в корень папки-эталона. После доставки файл появится в `<configDir>/snippets/example.css`. В M2 сохраняется поддержка корневых JSON, тем, сниппетов и `plugins/<id>/data.json`. Раскладки окон, кэш и собственная папка RefSync исключены. Автоматические триггеры в этой версии относятся к охвату «Контент».

## Ограничения

- Применение настроек проверяется на диске. Работающий сторонний плагин может пересохранить свой JSON из памяти. Категории, доставка кода плагинов, overlay и проверка после перезапуска запланированы на M3.
- Эталон M2 — локальная папка. Публичные папки Google Drive и Яндекс Диска и Git-подписка относятся к M4. OAuth и облачная публикация — к M5. Git-публикация — к M6.
- Сканирование использует SHA-256 и читает подходящие файлы целиком. Большие планы выводятся страницами по 50 строк. Текстовый diff ограничен 128 КиБ; для больших и бинарных файлов отображаются метаданные. Пустые каталоги отдельно не зеркалируются. Одновременные профили обслуживаются последовательно.
- Корзина RefSync и журнал отката хранят разные копии. Срок хранения корзины не удаляет staging и бэкапы завершённых транзакций. Их объём зависит от числа и размера доставок.
- Удалённые провайдеры, физические iOS/Android и системная корзина других ОС не входят в настольную проверку этой сборки.

## Дерево исходников и сборка

```text
refsync/
├── main.js, manifest.json                  установка
├── package.json, package-lock.json         зависимости
├── tsconfig.json, esbuild.config.mjs       TypeScript strict и сборка
├── src/
│   ├── main.ts, editor.ts, review.ts        команды, профили и план
│   ├── i18n.ts                             интерфейс RU/EN
│   ├── model.ts, profiles.ts, validator.ts   типы, миграция M1 и правила
│   ├── engine.ts, runtime.ts                очередь, события, лимиты ожидания
│   ├── scanner.ts, classifier.ts, filters.ts
│   ├── planner.ts, selection.ts, conflict-resolver.ts
│   └── applier.ts, state.ts, vault.ts       журнал, бэкапы и операции Obsidian
├── test/core.test.ts
├── scripts/package.py
└── README.md, THIRD_PARTY.txt
```

Из корня распакованных исходников с Node.js 22 и Python 3 выполните:

```sh
npm ci
npm test
npm run build
python3 scripts/package.py
```

Установочный архив и архив исходников появятся в `releases/`. Тесты охватывают миграцию, выбор операций, конфликты, фильтры и защиты удаления, очередь, отсрочки, тайм-аут записи, восстановление и откат.
