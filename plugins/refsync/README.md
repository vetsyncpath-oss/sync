# RefSync 0.3.0 · M3

RefSync доставляет файлы эталона в одну сторону. Профиль подписчика читает эталон и обновляет локальную папку. Издатель публикует в обратном направлении. В M3 обе папки находятся в одном хранилище Obsidian. Начните с двух непересекающихся тестовых папок.

## Установка и обновление с M1/M2

Для Obsidian 1.8.7 или новее. Отключите RefSync на время обновления. Распакуйте установочный ZIP **поверх** каталога `<действующая папка настроек>/plugins/`. При стандартной конфигурации файл плагина окажется в `.obsidian/plugins/refsync/main.js`. Включите RefSync в списке сторонних плагинов.

На Windows в Проводнике включите показ скрытых элементов. Откройте папку хранилища и скопируйте из ZIP папку `refsync` в `.obsidian\plugins\` (либо в `plugins` вашего каталога конфигурации). В самом редакторе профиля указывайте пути относительно хранилища, например `Папки\Эталон`.

При обновлении сохраните имеющиеся `refsync/data.json` и `refsync/runtime/`. Архив содержит только файлы поставки. При первом открытии новой версии прочитает профиль M1, сохранит его ID, папки и ручной режим запуска. Существующие резервные копии остаются доступны для отката. При сохранении настроек профиль записывается в новый формат списка.

## Первая доставка

1. Откройте **Настройки → RefSync**. Отредактируйте существующий профиль или добавьте новый. Новый профиль и дубликат изначально выключены. Введите имя, оставьте роль «Подписчик», выберите охват «Контент» и две отдельные папки. Кнопка «Создать недостающие папки» создаст их. Включите профиль и сохраните.
2. Поместите заметку в папку эталона. «Пробный план» показывает предстоящие действия. В режиме «План с подтверждением» кнопка «Применить эталон» открывает план, где можно исключить строки, посмотреть текстовые различия, выбрать действие по конфликту и скопировать план в JSON. Нажмите «Применить выбранное». Снятая галочка пропускает путь в текущем проходе.
3. Для автосинхронизации выберите «Тихий» и нужные триггеры. Доступны старт с задержкой, интервал, фокус окна, появление сети и изменения файлов. Интервал у новых профилей — пять минут. Нулевой интервал оставляет остальные выбранные триггеры. Обработка работает, пока Obsidian открыт и ОС разрешает приложению выполнение.
4. В списке профилей доступны дублирование, изменение порядка, выбор текущего, запуск одного или всех активных профилей и общая пауза. Команда «Откатить последнюю доставку» восстанавливает прежние байты и убирает созданные файлы текущего профиля. Откат заменяет последующие правки этих файлов.

## Политики контента

| Параметр | Поведение |
| --- | --- |
| Зеркало с сохранением | Сохраняет локальные файлы. При включённой передаче удалений в корзину попадают только ранее доставленные файлы, исчезнувшие из эталона. |
| Полное зеркало | Возвращает файлы к версии эталона и удаляет лишние файлы внутри фильтров. Защита удерживает удаления при пустом или резко уменьшившемся эталоне и при превышении заданных порогов. Команда «Разрешить выбранные отложенные удаления» открывает отдельный список для подтверждения по путям. |
| Конфликты | Предпочесть эталон, предпочесть цель, предпочесть более новый файл (допуск часов 2 секунды) или сохранить обе версии. Локальная копия получает суффикс с ID устройства и временем. |
| Удаления | Корзина RefSync с заданным сроком хранения, корзина хранилища, системная корзина при поддержке ОС или удаление после бэкапа. Корзина RefSync находится в `<configDir>/plugins/refsync/runtime/trash/`. Очистка просроченных записей выполняется при работе плагина. |
| Фильтры | Include/exclude glob через запятую, например `**/*.md,**/*.png`. Ограничение размера задаётся в МиБ и учитывает обе стороны. Исключённый путь защищён от удаления. |
| Открытые файлы | Недавняя правка в редакторе откладывает доставку затронутого файла. После заданного числа отсрочек применяется политика профиля с бэкапом. Издатель перед записью сверяет размер и время изменения источника с интервалом не менее двух секунд. |
| Сбои | Переходные блокировки повторяются с задержкой; занятый файл по возможности откладывается, другие файлы продолжают обработку. Если запись превысила тайм-аут, журнал сохраняется, а новые записи ждут завершения предыдущей операции и восстановления. |

## Папка настроек Obsidian

В профиле выберите охват «Настройки». Локальной стороной станет действующая папка конфигурации, которую Obsidian сообщает через `app.vault.configDir`. В эталоне храните её **содержимое**. Например, `snippets/example.css` будет доставлен в `<configDir>/snippets/example.css`.

1. В редакторе профиля выберите пресет или включите нужные категории. Доступны корневые JSON, оформление, темы, сниппеты, список community-плагинов, код, данные и прочие файлы плагинов. Для кода и данных имеются раздельные разрешающие и исключающие списки ID. В старом профиле M1/M2 сохраняются прежние категории и ручной запуск. Полную доставку кода включайте явно для эталона, которому доверяете: Obsidian исполняет доставленный JavaScript при загрузке соответствующего плагина.
2. Чтобы сохранить локальные поля JSON, укажите по одному правилу на строку. Например, `plugins/*/data.json => accounts[*].token` сохраняет токены учётных записей цели. Поддержаны ключи через точку, числовые индексы и wildcard. Для сравнения игнорируются порядок ключей, пробелы и UTF-8 BOM. Бэкап содержит прежние байты файла, включая локальные значения.
3. Выберите пакетное применение или только изменения. В пакетном режиме сначала проверяются и готовятся файлы плана. Ошибка чтения или записи возвращает исходное состояние. Очерёдность доставки — код и ресурсы, данные плагинов, корневые настройки, затем список включённых плагинов. При замене `data.json` RefSync временно выгружает ранее активный плагин и загружает его после записи, если Obsidian предоставляет соответствующие методы.
4. Перезагрузку можно выполнить сразу, при простое, отложить до следующего запуска или оставить отметку в строке состояния. Автоперезагрузки ограничены двумя за час с интервалом минимум пять минут. При следующей загрузке RefSync сверяет доставленные файлы с сохранённым пакетом и исправляет расхождения максимум дважды. Нерешённые пути попадают в журнал; повторная проверка не инициирует перезагрузку.
5. Команда отката возвращает прежние файлы из журнала. При доставке списка включённых плагинов RefSync сохраняет в нём свой ID. Чтобы снять остальные включения, поместите в эталон список `[]`. Собственная папка RefSync, раскладка окон, кэш и служебные каталоги защищены. На мобильных устройствах фильтр пропускает плагины с `isDesktopOnly` и исключает их ID из доставляемого списка.

**Windows.** Имена устройств (`CON`, `LPT1` и другие), двоеточия, конечные точки/пробелы и коллизии регистра или нормализации Unicode отмечаются в плане. Проблемные пути защищены также от удаления в полном зеркале. Занятые файлы повторно обрабатываются с задержкой. Windows CI собирает плагин, запускает тесты и открывает установочный ZIP в отдельном хранилище настоящего Obsidian.

## Ограничения

- Эталон M3 — вторая папка в том же хранилище. Публичные папки Google Drive и Яндекс Диска и Git-подписка относятся к M4, OAuth — к M5, Git-публикация — к M6.
- Профили настроек поддерживают ручной запуск, старт и интервал. Изменения рабочих раскладок не доставляются в работающее приложение. Для списков плагинов и правил JSON используются текстовые поля. Настройка применяется к существующим и новым файлам в пределах выбранного охвата.
- Сканирование использует SHA-256 и читает подходящие файлы целиком. Большие планы выводятся страницами по 50 строк. Текстовый diff ограничен 128 КиБ; для больших и бинарных файлов отображаются метаданные. Пустые каталоги отдельно не зеркалируются. Одновременные профили обслуживаются последовательно.
- Корзина RefSync и журнал отката хранят разные копии. После успешной проверки настроек удаляется временная копия пакета. Резервные копии отката хранятся отдельно от корзины.
- Удалённые провайдеры, физические iOS/Android и системная корзина других ОС не входят в настольную проверку этой сборки.

## Дерево исходников и сборка

```text
refsync/
├── main.js, manifest.json                  установка
├── package.json, package-lock.json         зависимости
├── tsconfig.json, esbuild.config.mjs       TypeScript strict и сборка
├── src/
│   ├── main.ts, editor.ts, review.ts        команды, профили и план
│   ├── i18n.ts                             интерфейс RU/EN
│   ├── model.ts, profiles.ts, validator.ts   типы, миграция M1 и правила
│   ├── config-scope.ts, scope-editor.ts    категории, пресеты и фильтр платформы
│   ├── json-overlay.ts, hot-config.ts      семантика JSON и применение data.json
│   ├── verify-settings.ts, reload-manager.ts проверка и перезагрузка
│   ├── engine.ts, runtime.ts                очередь, события, лимиты ожидания
│   ├── scanner.ts, classifier.ts, filters.ts
│   ├── planner.ts, selection.ts, conflict-resolver.ts
│   └── applier.ts, state.ts, vault.ts       журнал, бэкапы и операции Obsidian
├── test/core.test.ts
├── scripts/windows-smoke.py               интеграционная проверка на Windows
├── scripts/package.py
└── README.md, THIRD_PARTY.txt
```

Из корня распакованных исходников с Node.js 22 и Python 3 выполните:

```sh
npm ci
npm test
npm run build
python3 scripts/package.py
```

Установочный архив и архив исходников появятся в `releases/`. Тесты охватывают миграцию, выбор операций, конфликты, фильтры и защиты удаления, очередь, отсрочки, тайм-аут записи, восстановление и откат.
