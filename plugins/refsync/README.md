# RefSync 0.5.0 · M5

RefSync доставляет файлы эталона в одну сторону. Профиль подписчика читает эталон и обновляет локальную папку. Издатель публикует в обратном направлении. Для двух папок одного хранилища доступны обе роли. Публичные папки Google Диска, Яндекс Диска и репозитории Git по HTTPS доступны подписчику.

## Установка и обновление с M1–M4

Для Obsidian 1.8.7 или новее. Отключите RefSync на время обновления. Распакуйте установочный ZIP **поверх** каталога `<действующая папка настроек>/plugins/`. При стандартной конфигурации файл плагина окажется в `.obsidian/plugins/refsync/main.js`. Включите RefSync в списке сторонних плагинов.

На Windows в Проводнике включите показ скрытых элементов. Откройте папку хранилища и скопируйте из ZIP папку `refsync` в `.obsidian\plugins\` (либо в `plugins` вашего каталога конфигурации). В самом редакторе профиля указывайте пути относительно хранилища, например `Папки\Эталон`.

При обновлении сохраните имеющиеся `refsync/data.json` и `refsync/runtime/`. Архив содержит только файлы поставки. При первом открытии новой версии прочитает профиль M1, сохранит его ID, папки и ручной режим запуска. Существующие резервные копии остаются доступны для отката. При сохранении настроек профиль записывается в новый формат списка.

## Подключение личного облачного аккаунта

В **Настройки → RefSync → Аккаунты** выберите сервис и нажмите **Подключить аккаунт**. Один аккаунт можно использовать в нескольких профилях. На каждом устройстве войдите отдельно. При отзыве refresh-токена автоматические запуски профилей этого аккаунта приостанавливаются. В разделе **Аккаунты** видны статус и названия связанных профилей. Для восстановления нажмите **Войти через браузер** и выберите ту же учётную запись, OAuth-клиент и область доступа.

### Google Диск на Windows

1. Создайте проект в Google Cloud Console, включите **Google Drive API**, настройте экран согласия и добавьте свою почту в тестовые пользователи, если приложение находится в режиме тестирования.
2. Создайте **OAuth client ID → Desktop app**, скачайте JSON. В окне подключения Google выберите файл или вставьте содержимое в поле JSON. После успешного импорта появится сообщение «JSON-клиент загружен».
3. Для Desktop app оставьте поле адреса возврата пустым. Нажмите **Войти через браузер**. RefSync открывает системный браузер, выбирает свободный локальный порт и принимает ответ по `http://127.0.0.1:<порт>/`. После согласия вернитесь в Obsidian.
4. По умолчанию используется область `https://www.googleapis.com/auth/drive.file`. Google показывает файлы и папки, предоставленные этому OAuth-приложению. Для чтения существующего произвольного дерева явно включите **Доступ ко всему Диску** и подтвердите область `https://www.googleapis.com/auth/drive`.
5. Для мобильного клиента или ручного HTTPS-возврата создайте клиент типа **Web application**, зарегистрируйте свой точный HTTPS redirect URI и импортируйте его JSON. Используйте страницу под своим контролем. После входа скопируйте полный адрес возврата в поле RefSync и нажмите **Завершить вход**. RefSync проверяет `state`, а код обменивает с PKCE S256. Окно также принимает код, вручную скопированный в пределах текущей попытки входа.

[Настройка настольного OAuth-клиента Google](https://developers.google.com/identity/protocols/oauth2/native-app) · [Области доступа Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

### Яндекс Диск

1. Зарегистрируйте приложение в Яндекс OAuth. Для рабочего каталога приложения выберите права `cloud_api:disk.app_folder` и `cloud_api:disk.info`. Для доступа к другим каталогам зарегистрируйте `cloud_api:disk.read`, `cloud_api:disk.write` и `cloud_api:disk.info`.
2. Настройте адрес возврата. В RefSync по умолчанию указан `obsidian://refsync-oauth`. Если для вашей платформы в консоли доступен HTTPS redirect URI, зарегистрируйте собственный HTTPS-адрес и укажите его в RefSync. Оба значения должны совпадать.
3. Введите Client ID и, если требуется для вашего клиента, Client secret. Выберите ту же область доступа, что в консоли. Нажмите **Войти через браузер**. При ручном возврате вставьте код или полный URL из браузера и нажмите **Завершить вход**.
4. В режиме папки приложения пути считаются от `app:/`. При полном доступе они считаются от `disk:/`. Ссылки, выданные Яндексом для загрузки и скачивания, используются отдельно от авторизованных запросов к файловому API.

[Регистрация приложения Яндекса](https://oauth.yandex.ru/) · [API Яндекс Диска](https://yandex.com/dev/disk/)

### Публикация и подписка

В профиле выберите **Google Диск · OAuth** или **Яндекс Диск · OAuth**, подключённый аккаунт и роль. Для Google можно задать ID или ссылку на базовую папку. **Обзор папок источника** позволяет выбрать подкаталог. Путь в поле ниже задаётся относительно выбранного корня. Издатель может создать его кнопкой **Создать недостающие папки**. Для первой публикации удобно выделить отдельную папку на каждый охват.

- **Издатель** отправляет локальные заметки или выбранные файлы действующей папки настроек Obsidian в облако. Профиль использует обычные правила зеркала, фильтры и настройки тихих удалений. Google получает файлы через resumable upload, Яндекс выдаёт URL для загрузки. Удаления на стороне облака используют корзину сервиса. Локальный журнал RefSync хранит резервные копии для отката.
- **Подписчик** получает дерево из облака. После публикации в корне лежит `.sync-manifest.json` с ревизией, датой, ID устройства издателя, путями, размерами и SHA-256. При записи издатель сначала ставит отметку о незавершённой публикации, затем загружает файлы и последним записывает полный манифест. При остановке между этими шагами подписчик прерывает применение. Для папки без манифеста используется листинг. При выборе вложенного каталога манифест ищется в выбранном корне.
- Охват подписчика может быть уже опубликованного. При расхождении манифеста и выбранных файлов пробный план сообщит об ошибке. Для независимых издателей используйте разные каталоги. Сериализация запусков действует внутри одного экземпляра RefSync; распределённой блокировки между компьютерами у облачных API в этой версии нет.
- Аккаунт привязан к идентификатору пользователя сервиса, OAuth-клиенту и области доступа. Токены и client secret сохраняются в SecretStorage Obsidian, а в версиях до 1.11.4 — в локальном хранилище устройства. В `data.json` профиля записываются идентификатор подключения и местоположение папки. Для восстановления прерванной публикации или отката нужен доступ к тому же аккаунту. Если файл успели изменить в облаке, восстановление останавливается на расхождении. Сохраните стороннюю правку отдельно, восстановите опубликованную или исходную версию файла и повторите запуск профиля.
- Вход и refresh используют учётные данные вашего приложения. При ограничениях провайдера проверьте права, тестовых пользователей, redirect URI и доступ выбранного аккаунта к нужной папке. Тесты в поставке используют синтетические ответы сервисов. В CI на Windows реальный Obsidian открывает диалог выбора JSON, принимает локальный OAuth-возврат и проверяет публикацию, подписку и откат на тестовом Drive.

## Подключение публичного источника

В **Настройки → RefSync → Добавить** выберите источник эталона. Укажите локальную папку для заметок или выберите охват **Настройки** для доставки в действующую папку конфигурации Obsidian.

| Источник | Что ввести |
| --- | --- |
| Google Диск | Включите Google Drive API в своём проекте Google Cloud, создайте API-ключ с ограничением по API на Google Drive API и сохраните его в поле для этого устройства. Вставьте ссылку на папку с доступом «Все, у кого есть ссылка» или её ID. При наличии `resourcekey` используйте полную ссылку. |
| Яндекс Диск | Опубликуйте папку и вставьте ссылку вида `https://disk.yandex.ru/d/…` или публичный ключ API. Для чтения опубликованной папки достаточно этой ссылки. |
| Git | Скопируйте HTTPS-адрес клонирования публичного репозитория. Можно указать ветку, например `main`, или оставить поле пустым для ветки по умолчанию. Понадобится сервер с поддержкой Git smart HTTP и shallow fetch. |

Нажмите **Обзор папок источника**, откройте вложенную папку и нажмите **Выбрать эту папку**. Можно также ввести путь вручную. Для настроек выберите каталог, непосредственно содержащий `app.json`, `themes/` и другие нужные файлы, например `.obsidian` в Git. Создайте локальную папку кнопкой в редакторе, включите профиль, сохраните и откройте **Пробный план**.

API-ключ Google хранится в локальном хранилище Obsidian для этого устройства. Публичная ссылка сохраняется в профиле. Сбой листинга или неоднозначные имена останавливают доставку. Перед локальным удалением из облачного зеркала RefSync повторно читает соответствующие каталоги. Google Docs, Sheets, ярлыки, символические ссылки Git и подмодули пропускаются. Git LFS доставляется как файл-указатель.

Подписка Git читает дерево одного коммита. Его дата служит временем изменения для политики «Предпочесть более новый». После shallow fetch объекты остаются в `<configDir>/plugins/refsync/runtime/git/`. На мобильном устройстве учитывайте размер всего снимка ветки, даже если для доставки выбрана одна подпапка.

## Первая доставка

1. Откройте **Настройки → RefSync**. Отредактируйте существующий профиль или добавьте новый. Новый профиль и дубликат изначально выключены. Введите имя, оставьте роль «Подписчик», выберите охват «Контент» и две отдельные папки. Кнопка «Создать недостающие папки» создаст их. Включите профиль и сохраните.
2. Поместите заметку в папку эталона. «Пробный план» показывает предстоящие действия. В режиме «План с подтверждением» кнопка «Применить эталон» открывает план, где можно исключить строки, посмотреть текстовые различия, выбрать действие по конфликту и скопировать план в JSON. Нажмите «Применить выбранное». Снятая галочка пропускает путь в текущем проходе.
3. Для автосинхронизации выберите «Тихий» и нужные триггеры. Доступны старт с задержкой, интервал, фокус окна, появление сети и изменения файлов. Интервал у новых профилей — пять минут. Нулевой интервал оставляет остальные выбранные триггеры. Обработка работает, пока Obsidian открыт и ОС разрешает приложению выполнение.
4. В списке профилей доступны дублирование, изменение порядка, выбор текущего, запуск одного или всех активных профилей и общая пауза. Команда «Откатить последнюю доставку» восстанавливает прежние байты и убирает созданные файлы текущего профиля. Откат заменяет последующие правки этих файлов.

## Политики контента

| Параметр | Поведение |
| --- | --- |
| Зеркало с сохранением | Сохраняет локальные файлы. При включённой передаче удалений в корзину попадают только ранее доставленные файлы, исчезнувшие из эталона. |
| Полное зеркало | Возвращает файлы к версии эталона и удаляет лишние файлы внутри фильтров. Защита удерживает удаления при пустом или резко уменьшившемся эталоне и при превышении заданных порогов. Команда «Разрешить выбранные отложенные удаления» открывает отдельный список для подтверждения по путям. |
| Защита от массовых удалений в тихом режиме | По умолчанию включена и при обновлении, и для новых профилей. Выключите её в редакторе профиля, чтобы тихая доставка выполняла все удаления по правилам зеркала при любом количестве и проценте, в том числе при пустом или резко уменьшившемся эталоне. Это действует и при наследовании тихого режима. Пробный план показывает эффект следующего запуска. При просмотре перед первой доставкой действуют обычные пороги. |
| Конфликты | Предпочесть эталон, предпочесть цель, предпочесть более новый файл (допуск часов 2 секунды) или сохранить обе версии. Локальная копия получает суффикс с ID устройства и временем. |
| Удаления | Корзина RefSync с заданным сроком хранения, корзина хранилища, системная корзина при поддержке ОС или удаление после бэкапа. Корзина RefSync находится в `<configDir>/plugins/refsync/runtime/trash/`. Очистка просроченных записей выполняется при работе плагина. |
| Фильтры | Include/exclude glob через запятую, например `**/*.md,**/*.png`. Ограничение размера задаётся в МиБ и учитывает обе стороны. Исключённый путь защищён от удаления. |
| Открытые файлы | Недавняя правка в редакторе откладывает доставку затронутого файла. После заданного числа отсрочек применяется политика профиля с бэкапом. Издатель перед записью сверяет размер и время изменения источника с интервалом не менее двух секунд. |
| Сбои | Переходные блокировки повторяются с задержкой; занятый файл по возможности откладывается, другие файлы продолжают обработку. Если запись превысила тайм-аут, журнал сохраняется, а новые записи ждут завершения предыдущей операции и восстановления. |

## Папка настроек Obsidian

В профиле выберите охват «Настройки». Локальной стороной станет действующая папка конфигурации, которую Obsidian сообщает через `app.vault.configDir`. В эталоне храните её **содержимое**. Например, `snippets/example.css` будет доставлен в `<configDir>/snippets/example.css`.

1. В редакторе профиля выберите пресет или включите нужные категории. Доступны корневые JSON, оформление, темы, сниппеты, список community-плагинов, код, данные и прочие файлы плагинов. Для кода и данных имеются раздельные разрешающие и исключающие списки ID. В старом профиле M1/M2 сохраняются прежние категории и ручной запуск. Полную доставку кода включайте явно для эталона, которому доверяете: Obsidian исполняет доставленный JavaScript при загрузке соответствующего плагина.
2. Чтобы сохранить локальные поля JSON, укажите по одному правилу на строку. Например, `plugins/*/data.json => accounts[*].token` сохраняет токены учётных записей цели. Поддержаны ключи через точку, числовые индексы и wildcard. Для сравнения игнорируются порядок ключей, пробелы и UTF-8 BOM. Бэкап содержит прежние байты файла, включая локальные значения.
3. Выберите пакетное применение или только изменения. В пакетном режиме сначала проверяются и готовятся файлы плана. Ошибка чтения или записи возвращает исходное состояние. Очерёдность доставки — код и ресурсы, данные плагинов, корневые настройки, затем список включённых плагинов. При замене `data.json` RefSync временно выгружает ранее активный плагин и загружает его после записи, если Obsidian предоставляет соответствующие методы.
4. Перезагрузку можно выполнить сразу, при простое, отложить до следующего запуска или оставить отметку в строке состояния. Автоперезагрузки ограничены двумя за час с интервалом минимум пять минут. При следующей загрузке RefSync сверяет доставленные файлы с сохранённым пакетом и исправляет расхождения максимум дважды. Нерешённые пути попадают в журнал; повторная проверка не инициирует перезагрузку.
5. Команда отката возвращает прежние файлы из журнала. При доставке списка включённых плагинов RefSync сохраняет в нём свой ID. Чтобы снять остальные включения, поместите в эталон список `[]`. Собственная папка RefSync, раскладка окон, кэш и служебные каталоги защищены. На мобильных устройствах фильтр пропускает плагины с `isDesktopOnly` и исключает их ID из доставляемого списка.

**Windows.** Имена устройств (`CON`, `LPT1` и другие), двоеточия, конечные точки/пробелы и коллизии регистра или нормализации Unicode отмечаются в плане. Проблемные пути защищены также от удаления в полном зеркале. Занятые файлы повторно обрабатываются с задержкой. Windows CI собирает плагин, запускает тесты и открывает установочный ZIP в отдельном хранилище настоящего Obsidian.

## Ограничения

- Публикация в Git запланирована на M6.
- Профили настроек поддерживают ручной запуск, старт и интервал. Изменения рабочих раскладок не доставляются в работающее приложение. Для списков плагинов и правил JSON используются текстовые поля. Настройка применяется к существующим и новым файлам в пределах выбранного охвата.
- Сканирование использует SHA-256 и читает подходящие файлы целиком. Большие планы выводятся страницами по 50 строк. Текстовый diff ограничен 128 КиБ; для больших и бинарных файлов отображаются метаданные. Пустые каталоги отдельно не зеркалируются. Одновременные профили обслуживаются последовательно.
- Корзина RefSync и журнал отката хранят разные копии. После успешной проверки настроек удаляется временная копия пакета. Резервные копии отката хранятся отдельно от корзины.
- Физические iOS/Android и системная корзина других ОС не входят в настольную проверку этой сборки.

## Дерево исходников и сборка

```text
refsync/
├── main.js, manifest.json                  установка
├── package.json, package-lock.json         зависимости
├── tsconfig.json, esbuild.config.mjs       TypeScript strict и сборка
├── src/
│   ├── main.ts, editor.ts, review.ts        команды, профили и план
│   ├── accounts.ts, oauth-ui.ts             аккаунты, PKCE и импорт клиента
│   ├── private-cloud.ts, cloud-manifest.ts  запись в облако, ревизии и манифест
│   ├── public-store.ts, public-location.ts  публичный эталон и его адрес
│   ├── public-cloud.ts, public-git.ts        Drive v3, публичный Диск, Git smart HTTP
│   ├── git-fs.ts, git-buffer.ts             кэш Git в адаптере Obsidian
│   ├── remote-browser.ts                   выбор удалённого каталога
│   ├── i18n.ts                             интерфейс RU/EN
│   ├── model.ts, profiles.ts, validator.ts   типы, миграция M1 и правила
│   ├── config-scope.ts, scope-editor.ts    категории, пресеты и фильтр платформы
│   ├── json-overlay.ts, hot-config.ts      семантика JSON и применение data.json
│   ├── verify-settings.ts, reload-manager.ts проверка и перезагрузка
│   ├── engine.ts, runtime.ts                очередь, события, лимиты ожидания
│   ├── scanner.ts, classifier.ts, filters.ts
│   ├── planner.ts, selection.ts, conflict-resolver.ts
│   └── applier.ts, state.ts, vault.ts       журнал, бэкапы и операции Obsidian
├── test/core.test.ts, test/public.test.ts, test/cloud.test.ts
├── scripts/oauth-smoke.py                 OAuth в установленном ZIP
├── scripts/windows-smoke.py               интеграционная проверка на Windows
├── scripts/package.py
└── README.md, THIRD_PARTY.txt
```

Из корня распакованных исходников с Node.js 22, Git (для тестового сервера) и Python 3 выполните:

```sh
npm ci
npm test
npm run build
python3 scripts/package.py
```

Установочный архив и архив исходников появятся в `releases/`. Тесты охватывают миграцию, выбор операций, конфликты, фильтры и защиты удаления, очередь, отсрочки, тайм-аут записи, восстановление и откат.
