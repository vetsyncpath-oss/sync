# RefSync 0.1.0 · M1

RefSync доставляет содержимое эталона в одну сторону. В этой сборке эталоном служит вторая папка того же хранилища. Подписчик получает файлы из неё, издатель записывает в неё. Направление видно в выборе роли. Для первого знакомства используйте отдельное тестовое хранилище.

## Установка и первая доставка

1. В Obsidian 1.8.7 или новее распакуйте установочный ZIP в каталог `plugins` **действующей папки конфигурации хранилища**. При стандартном расположении получится `.obsidian/plugins/refsync/manifest.json` рядом с `main.js`. При переопределённой папке используйте её. Обновите список установленных сторонних плагинов и включите **RefSync**.
2. Откройте настройки RefSync. Оставьте роль «Подписчик» и охват «Контент». Нажмите «Создать недостающие папки», затем «Сохранить». Положите заметку в `RefSync-reference`.
3. Через палитру команд откройте **RefSync → Пробный план**. Чтобы доставить файлы, вызовите **Применить эталон**, проверьте различия и подтвердите применение. Заметка появится в `RefSync-copy`. Повторный запуск с тем же эталоном пропустит доставленную версию.
4. Для проверки **самих настроек Obsidian** переключите охват на «Настройки». В качестве эталона укажите отдельную папку, например `RefSync-config-reference`, создайте её той же кнопкой и сохраните профиль. Положите в неё `snippets/example.css`. После применения копия появится в `<configDir>/snippets/example.css`. Путь в эталоне начинается со `snippets/` и повторяет структуру **внутри** папки настроек.
5. Выберите **Откатить последнюю доставку**. RefSync вернёт прежние байты заменённых файлов и уберёт созданные файлы этой доставки. Это также заменит более поздние правки восстановленных файлов. Откат выполняется для выбранных роли, пары и охвата.

## Состав этапа

| Часть | Что можно проверить |
| --- | --- |
| Сканирование | Рекурсивный обход через адаптер видит изменения на диске. Настройки читаются из `app.vault.configDir`. Коллизия путей или неполное чтение прерывают план. |
| Настройки | Доставляются корневые JSON конфигурации, `themes/<имя>/{manifest.json,theme.css}`, CSS-сниппеты и `plugins/<id>/data.json`. Перед записью проверяется синтаксис JSON. Раскладка окон, кэш и собственный каталог RefSync исключены. |
| Сравнение | Для обычных файлов используется SHA-256. Эталонная версия, последняя применённая версия и признак доставки сохраняются по устройству, паре и охвату. Локальное пересохранение горячего JSON само по себе не вызывает повторную доставку. |
| Планировщик | В ядре есть полное зеркало, сохранение локальных файлов, учёт доставленных удалений и четыре политики конфликтов. Интерфейс M1 использует сохранение локальных файлов, выключенные удаления и предпочтение эталона. |
| Применение | Сначала готовится полная копия изменений. Перед каждой записью сохраняются фактические байты цели и отметка в журнале. Сбой вызывает откат, а незаконченная транзакция восстанавливается при загрузке плагина. При пустом или резко сократившемся эталоне либо большом числе удалений планировщик удерживает удаления. |
| Управление | Один редактируемый профиль, ручной запуск, просмотр плана, откат, статус в боковой ленте и строке состояния desktop. Языки RU/EN. Журнал событий находится в `<configDir>/plugins/refsync/runtime/events.jsonl` с одной ротацией по размеру. Состояние сравнения хранится в локальном хранилище Obsidian. |

## Ограничения сборки

- Локальный провайдер требует двух непересекающихся корней в одном хранилище. Для охвата «Контент» с этим провайдером пара с корнем всего хранилища пересеклась бы с эталоном.
- Изменения настроек в M1 проверяются на диске. Запущенный плагин может пересохранить свой JSON из памяти. Выбор категорий, доставка кода плагинов, горячее применение, фильтрация по платформам, overlay и проверка после перезапуска входят в M3. Пустые каталоги отдельно не зеркалируются.
- Бэкапы и staging хранятся в закрытом для синхронизации каталоге плагина. Автоматической очистки завершённых транзакций в M1 нет. Место на диске зависит от объёма и числа доставок.
- Тихий режим, автозапуск и список профилей относятся к M2. Публичные Яндекс Диск, Google Drive и Git входят в M4, облачная авторизация и публикация — в M5, Git-публикация — в M6.
- Настольный прогон выполнен в Obsidian 1.15.1 на Linux. Проверены предварительный план, запись, повторный запуск, JSON в каталоге конфигурации и откат. Нестандартное имя каталога покрыто тестами ядра. Испытания на физических iOS/Android относятся к дальнейшим этапам.

## Исходники и сборка

```text
refsync/
├── manifest.json, main.js                  метаданные и готовый плагин
├── package.json, package-lock.json         зафиксированные зависимости
├── tsconfig.json, esbuild.config.mjs       strict TypeScript и сборка
├── src/
│   ├── main.ts, i18n.ts                    Obsidian UI, команды, журнал, RU/EN
│   ├── engine.ts                          оркестрация и состояние интерфейса
│   ├── model.ts, validator.ts              профиль, StorageProvider, правила
│   ├── scanner.ts, classifier.ts           обход, фильтры, классы H/S/V
│   ├── planner.ts, conflict-resolver.ts    план и стратегии разрешения конфликтов
│   ├── applier.ts, state.ts                доставка, снимки, журнал и откат
│   └── vault.ts                           локальные адаптеры Obsidian
├── test/core.test.ts                      тесты с провайдером в памяти
├── scripts/package.py                     упаковка проверяемых ZIP
└── README.md
```

В каталоге исходников с Node.js 22 и npm выполните:

```sh
npm ci
npm test
npm run build
python3 scripts/package.py
```

В `releases/` появятся установочный архив с папкой `refsync/` и отдельный архив полного исходного кода. Для установки из исходников достаточно собрать и скопировать `main.js` и `manifest.json` по пути из шага 1.

Следующий этап — **M2, охват «Контент»**. В него входят управление несколькими профилями, политики в редакторе, тихий режим, триггеры, отложенная запись открытых файлов и план с выбором действий.
