# Sync Studio 0.1.0 — desktop alpha

Новый плагин Obsidian с профилями, центром операций и мастером импорта. Это установочная alpha-сборка для проверки на копии vault, а не объявление готовности к работе с единственным экземпляром данных. Реальные аккаунты и запущенный Obsidian в среде разработки отсутствовали.

## Установка

1. Нужен настольный Obsidian **1.11.4 или новее** (Secret Storage).
2. Распакуйте папку `sync-studio` из установочного архива в `<vault>/.obsidian/plugins/`. При нестандартной папке конфигурации используйте её вместо `.obsidian`.
3. Отключите прежний синхронизатор для тех же файлов. Одновременная работа нескольких синхронизаторов или двух процессов Obsidian с одним vault не поддерживается.
4. Перезапустите Obsidian и включите Sync Studio в Community plugins.
5. Откройте Sync Studio через ленту или командную палитру. Добавьте подключение, создайте **новый** профиль и нажмите «Проверить изменения».

Никакие профили, настройки или токены старого плагина не читаются и не мигрируются. По умолчанию автосинхронизация выключена, удаления не распространяются, конфликты сохраняются в двух версиях.

## Что реализовано

| Возможность | Состояние |
|---|---|
| Профили и независимые подключения | Реализованы с новым форматом данных |
| Категории, папки, исключения без упорядоченных glob | Реализованы |
| Ручной план и выполнение | Реализованы; план проверяется перед записью |
| Расписание, старт, события изменения vault | Реализованы; работают только при открытом Obsidian |
| Получение / отправка / двусторонняя работа | Реализованы для записываемых адаптеров |
| Конфликт: локальный / удалённый / новый / обе / спросить | Реализованы; «новый» требует доступного времени обеих сторон |
| Удаления: игнорировать / корзина / окончательно | Реализованы; только для ранее отслеживаемых файлов |
| Google OAuth | Переиспользован изолированный PKCE-поток из предоставленного архива |
| Произвольные существующие папки Google Drive | Новый адаптер без app-managed namespace |
| Публичная папка Drive | Только получение, нужен API key |
| Яндекс Диск | Новый REST-адаптер, OAuth-токен вводится вручную |
| GitHub | Публичные/приватные репозитории, ветка/тег и подкаталог; только получение |
| Внешняя папка компьютера → Drive/Яндекс | Реализована как источник только для чтения |
| Один облачный сервис → другой | Реализован отдельным профилем импорта через устройство |
| Настройки Obsidian и data.json плагинов | Реализованы как независимые категории |

Google OAuth: создайте в Google Cloud клиент типа **Desktop app**, включите Drive API и загрузите JSON клиента в настройках подключения. Запрашивается `drive` для уже существующих файлов, а не только `drive.file`. Настройка consent screen, тестовые пользователи и требования Google к публикации OAuth-приложения остаются необходимыми. Секреты хранятся через Obsidian Secret Storage; в `data.json` остаются только ссылки на них. Публичный Drive требует собственного API key проекта с включённым Drive API.

Для Яндекс Диска нужен OAuth-токен с правами чтения и записи для отправки. Для GitHub можно оставить токен пустым у публичного репозитория; для приватного нужен токен с Contents: read. API-токены не вводятся в профили.

## Семантика синхронизации

- «Получать» не является зеркалом: локальные файлы, никогда не существовавшие в источнике, не удаляются.
- Размер и время не определяют равенство. Сравнивается SHA-256 содержимого; серверная версия используется отдельно для проверки актуальности.
- История принадлежит паре endpoint и профилю. Смена корня или аккаунта не наследует прежние удаления.
- При одинаковой паре версий и неизменной политике решение не повторяется. Смена политики пересматривает ранее принятое расхождение.
- При «не распространять удаления» сохранённая история не уничтожается: последующее включение удаления может применить его.
- Переименование обрабатывается как новый файл и исчезновение старого. При выключенных удалениях старый путь остаётся.
- Изменение scope исключает файл из управления, но не удаляет его.
- Конфликтные копии: `.sync-conflicts/<runId>/<путь>`. В двустороннем режиме основная версия при keep-both становится удалённой, локальная сохраняется в копии на устройстве.
- Резервные версии перед обычной перезаписью: `.sync-studio/recovery/<runId>/<путь>`. Автоматическая очистка пока отсутствует; резервные данные занимают место.
- Окончательное удаление не создаёт отдельной резервной копии. Корзина на локальной стороне — `.trash` Obsidian; удалённая корзина зависит от сервиса.
- Неопределённое или неполное чтение источника останавливает план. Файлы сверх лимита исключаются, а не считаются удалёнными.
- Неразрешённые конфликты не выполняются. Остальные операции можно применить отдельно.

## Существенные ограничения alpha

- **Нет испытаний в реальном Obsidian и живых аккаунтах.** API-адаптеры проверены на моделируемых ответах, файловая запись — на реальных временных каталогах с моделью API Obsidian.
- Только desktop; нет мобильного OAuth и гарантий фонового исполнения при закрытом приложении.
- **Код плагинов не заменяется.** Категория доступна для плана, операции блокируются до отдельной пакетной установки. Настройки плагинов синхронизируются отдельно. Менеджера обновления релизов нет.
- GitHub: нет отправки, Git LFS, submodules и symlinks. Файловое mtime не выдумывается из времени общего коммита.
- Google Docs и shortcuts требуют отдельного экспорта; их обнаружение сейчас останавливает обход. Выбирайте корень с обычными файлами. Полноценные Shared Drives специально не тестировались.
- Изменение существующих файлов Drive требует ETag для If-Match. При отсутствии ETag перезапись/удаление останавливаются, а не выполняются без проверки версии.
- Яндекс Диск не предоставляет используемому API атомарную операцию compare-and-swap. Выполняется повторная проверка перед записью, но внешняя конкурентная запись в промежутке не исключена. Не редактируйте назначение другим клиентом во время отправки.
- Импорт между подключениями одного сервиса пока запрещён, чтобы исключить рекурсивный перенос дерева внутрь самого себя. Импорт между разными сервисами и из внешней папки доступен.
- Состав пока не включает конструктор произвольных логических условий и локальные переопределения политик по папке. Они остаются следующим этапом относительно HTML-макета.
- Пустые папки не переносятся. Нет оптимизации переименований и блочной передачи. Размер по умолчанию ограничен 50 МБ, файл передаётся целиком, последовательно. Первое чтение GitHub и Drive без SHA-256 может потребовать загрузки содержимого для вычисления хеша.
- Пересечение локальных корней с активными профилями блокируется консервативно даже при непересекающихся исключениях. Не назначайте нескольким профилям один и тот же удалённый каталог для записи.
- Формат имён ограничен переносимыми путями Windows/macOS/Linux; ссылки и коллизии регистра/Unicode не разрешаются автоматически.
- Не реализованы распределённые version vectors и координация произвольного числа независимых клиентов. Это синхронизация пары endpoint с локальным подтверждённым состоянием.
- Сетевой транспорт использует Node HTTPS. Особые системные прокси и нестандартные сертификаты отдельно не проверены.

## Хранение и восстановление

`data.json` нового плагина содержит только новые подключения без секретов, профили и последние 100 отчётов. `.sync-studio/state-v1.json` — отдельное атомарное состояние с контрольной суммой, подтверждёнными парами и незавершённой операцией. Это новая минимальная реализация, не журнал из старого архива.

Локальная запись: временный файл → проверка содержимого → fsync → повторная проверка оригинала → замена. Состояние фиксируется после выполнения. При возобновлении незавершённая операция сверяется только с её исходным намерением/подтверждением; позднейшие изменения не считаются синхронизированными. При неоднозначности запись блокируется. Сообщение указывает файл; его предыдущую версию можно взять из recovery или conflict-каталога. Не удаляйте файл состояния как способ «исправить конфликт»: это уничтожит историю удалений.

## Разработка и проверки

Node.js 22+:

```sh
npm ci
npm test
npm run build
```

Сборка: `dist/sync-studio/{main.js,manifest.json,styles.css}`. Исходники — TypeScript без старого UI. Описание архитектуры и происхождения: `ARCHITECTURE.md`, `THIRD_PARTY.md`. Набор тестов включает модель планирования, сохранение решений, реальные временные файлы, сбои checkpoint/intent, восстановление и контрактные ответы API. Он не заменяет end-to-end испытания с сервисами.
