# Проверка работы Studio 0.3.0

## Первый полный цикл

1. Создайте отдельную папку облачного сервиса и положите в неё `check.md` с простым текстом.
2. В Studio откройте «Подключения», выберите сервис, выполните авторизацию/введите токен, выберите эту папку, проверьте доступ.
3. Нажмите «Сохранить и создать профиль». Нажмите «Изменить». Задайте локальную папку `Sync-check`, направление «Получать»; автозапуск оставьте выключенным. Нажмите «Сохранить».
4. «Проверить изменения» должен предложить получение `check.md`. Выполните план и откройте локальный файл.
5. Измените удалённый файл и повторите: должна обновиться локальная копия. Предыдущая версия находится в `.sync-studio/recovery/`.
6. После первого успешного переноса нажмите «Изменить», выберите политику удаления «Корзина» и нажмите «Сохранить», удалите файл в источнике, проверьте план. Удаление распространяется только на ранее отслеживаемые файлы.
7. Для проверки отправки создайте новый локальный файл и измените направление на «Отправлять» через «Изменить» → «Сохранить». Проверьте план, затем результат в сервисе.

## «Коллизия» в Google Drive

Drive разрешает несколько файлов или папок с одинаковым именем. Обычный каталог vault не может представить их одним путём. Кроме того, имена `Note.md` и `note.md` конфликтуют на нечувствительных к регистру файловых системах.

Studio показывает конкретные пути. Объекты за пределами scope и исключённые пути не блокируют запуск. Если коллизия внутри выбранного состава, доступны варианты:

- переименовать дубль в Google Drive, затем повторить проверку;
- нажать «Исключить конфликтующие пути из профиля». Это добавит точные пути в исключения; файлы не изменятся. После этого повторить проверку.
- для получения одноимённых файлов: «Изменить» → «Изменения» → «Одноимённые файлы в Drive» → «Получать новейший дубль (по Sync Engine)» → «Сохранить». В плане будет предупреждение с выбранным ID. Дубли папок и коллизии регистра этот режим не разрешает.

Плагин не выбирает случайный дубль и не удаляет его. Если ошибка остаётся после сужения scope, скопируйте диагностику из сообщения. Она содержит версию, сообщение, пути коллизии и последние результаты, но не токены/ключи. Имена файлов и текст ошибок могут содержать личные сведения — проверьте текст перед отправкой.

## Удаление включено, но лишний файл остаётся

В режиме отслеживания файл должен раньше существовать в источнике и попасть в успешно сохранённую историю этого профиля. Файл, существовавший только в назначении, сохраняется. Для полного соответствия источнику выберите «Изменения» → «Режим одного направления» → «Зеркало», включите нужную политику удаления и просмотрите план: удаление лишних файлов действует уже при первом запуске.

Лимит размера и исключения действуют в обоих режимах. Пустые папки не удаляются отдельно. Коллизия файла с папкой требует решения до синхронизации.

## Незавершённая операция

После ошибки используйте «Перепроверить файлы». Повторное применение старого плана заблокировано, пока не обработана pending-операция. Если её путь исключён или превышает новый лимит, сначала верните прежнюю область/лимит профиля. Это позволяет восстановить результат по реальным файлам, а не принять исключённый файл за удалённый.

## Google подключён, но перенос не начинается

Авторизация аккаунта и выбор папки — отдельные шаги. Проверьте папку в форме подключения и сохраните её. В профиле нужен непустой удалённый корень. Для существующего подключения можно повторно войти без повторной вставки client JSON, если сохранены параметры клиента.

HTTP 401: повторите вход. HTTP 403: проверьте Drive API, выданные OAuth-права и доступ аккаунта к папке. Публичный режим требует API key и папку с доступом по ссылке. Google Docs и shortcuts требуют экспорта, поэтому пропускаются с предупреждением.

Если Drive не вернул ETag, запись поверх существующего файла и удаление останавливаются. Проверка версии не отключается автоматически; нужна диагностика конкретного ответа API.

## Яндекс Диск

Используется OAuth-токен Яндекса, не Google JSON. Корень диска — `disk:/`, вложенная папка — `disk:/Notes`. Браузер папок показывает каталоги Яндекс Диска. Для записи токен должен иметь соответствующие права.

Перенаправления скачивания разрешены только по HTTPS внутри доменов Яндекса; заголовки авторизации не пересылаются на другой сервер. HTTP 404 означает неверный путь или отсутствие доступа; HTTP 403 — отказ в правах.

## Где посмотреть ошибку

Ошибка проверки остаётся над рабочим пространством и в «Истории». Ошибка выполнения оставляет окно плана открытым; «Перепроверить файлы» строит новый план. Выполненные до ошибки действия сохраняют своё подтверждённое состояние. Не удаляйте файл состояния для устранения ошибки: это уничтожает историю удалений.

## Что проверено в разработке

`npm run verify` запускает тесты ядра/адаптеров/транспорта, DOM-интеграционные сценарии, TypeScript и сборку. DOM-тесты используют настоящее представление Studio и контроллер, модель API Obsidian, реальные временные файлы и моделируемые облачные API. Вход через браузер Google моделируется; обработка токенов проверяется отдельно. Реальные аккаунты, сетевые ограничения конкретного устройства и поведение файлового наблюдателя запущенного Obsidian требуют проверки на устройстве.
