# Согласованный UI синхронизации

Следующий этап UI для per-job/pull+Drive описан в [Overhaul vNext UI](overhaul-vnext/05-ui.md). Ниже сохранён контракт прежнего pull этапа; path-only remote tree, общий running gate и запрет всех `.conflict-*` не переносятся в новые Drive flows.

Исходная ветка: `overhaul/2b1-recovered`, commit `567f8c5c5b3f528d0c86b3210c44b562de77c02c`.
Этот этап объединяет настройку области, подключений и поведения, подробный план,
состояние запуска и восстановление. Синхронизация остаётся **источник → vault**.

## Модель интерфейса

Три независимых вопроса для каждого пути:

1. **Участие:** включён, исключён или наследует область родителя.
2. **Источник:** конкретное подключение и путь в нём, либо наследование.
3. **Поведение:** профиль записи, удаления и разрешения конфликтов.

Подключение содержит адрес и реквизиты провайдера. Профиль содержит поведение.
Назначение связывает их с конечным путём vault. Создание подключения само по себе
не меняет назначения. Общий источник используется только там, где нет собственного.
Пустой общий источник означает «Только назначения».

Рабочее окно доступно из настроек, команды и панели запуска. На широком экране
это подключения, дерево и инспектор. На узком — вкладки «Источники», «Файлы»,
«Назначение» с сохранением контекста. Панели прокручиваются внутри окна, кнопки
сохранения и запуска остаются доступны.

## Область и дерево

«Весь vault» временно отключает ограничения выбранных областей, но сохраняет
пользовательские исключения, перенаправления и назначения. Предыдущий выбор
папок хранится отдельно в `scopeSelection.customFolders`. Возврат к выбранным
областям восстанавливает его. Переход из нового полного vault в выбранные области
начинается с исключённого корня, а не с неявно включённого всего vault.

«Настройки Obsidian» включает `.obsidian`. Явное включение другой папки переводит
область в «Выбранные области», чтобы название соответствовало действующим правилам.
Повторное включение исключённой папки заменяет её правило без создания дубликатов.

Строка дерева — `treeitem`, имя — текст. Отдельная кнопка раскрывает папку.
Чекбокс выделяет область для массового редактирования и не означает разрешение
синхронизации. Стрелки перемещают фокус и раскрывают папки; Enter открывает
назначение, Space выделяет; Home/End перемещаются по видимой странице.
Дерево и список путей источника показывают до 150 строк на странице.

Статусы файлов используют ту же политику включения, исключений и разрешений,
что и исполнение. Папка может иметь несколько источников и смешанное поведение.
Наличие в снимке источника не означает, что файл обязательно будет перезаписан.
Ошибочный refresh сохраняет предыдущий снимок с отметкой устаревания.

Исключения редактируются отдельно. Переключатель расположения панелей Obsidian
меняет реальные исключения `workspace.json` и `workspace-mobile.json`.
Разрешения на код плагинов и сниппетов остаются в настройках плагина.

## Черновик и назначения

Все поля инспектора участвуют в черновике, включая ещё не применённую форму.
Выбор другой строки, refresh, смена общего источника и переход между источниками
сохраняют введённые значения. Для разных источников формы помнят отдельные пути.
«Применить к черновику» не запускает синхронизацию. «Сохранить настройки» проверяет
и сохраняет политику, подключения и библиотеку профилей вместе; окно остаётся открытым.

Закрытие изменённого окна предлагает сохранить, отбросить или вернуться.
Предпросмотр требует сохранённого состояния. Изменения внешних настроек или
начавшееся исполнение запрещают сохранять устаревший черновик.
Если другой инспектор изменил то же назначение, незавершённая форма показывает
предупреждение: автоматическое сохранение не заменяет его молча. Можно сбросить
поля либо явно применить свой вариант.

«Добавить назначение» создаёт дополнительное правило имён, сохраняя правило
«Все файлы». Фильтр — точные имена через запятую во всём поддереве.
Подсказки «Код плагинов» и `data.json` появляются только внутри `.obsidian/plugins`.
Редактирование фильтрованного правила сохраняет его селектор.
Подключения и профили, используемые назначениями или незавершёнными формами,
нельзя удалить без изменения этих назначений.

Формы подключений используют одну схему в рабочем окне и библиотеке.
Некорректные и обязательные поля показывают ошибку рядом с полем.
Секреты маскируются; значения разных провайдеров сохраняются при переключении
в пределах открытого редактора. Проверка доступа и чтение содержимого — разные действия.
Для ZIP показано, что просмотр может скачать архив целиком.

## Запуск источников по очереди

1. Создать подключения A и B.
2. Связать их с нужными конечными областями vault и сохранить настройки.
3. В действиях A выбрать «Синхронизировать этот источник» и проверить план.
4. Затем открыть рабочее окно и выполнить то же для B.

При запуске A читается только A. Победившие назначения всех подключений остаются
действующими: область B не становится областью A. Запуск не записывает, не удаляет,
не чистит кэш и очередь B. Оба запуска используют один namespace конфигурации
маршрутов. Несвязанные ошибки B не блокируют удаления или результат A.

Общий запуск получает свежие снимки всех участвующих источников до записи.
Если необходимый источник недоступен, план не может разрешить удаления на основании
неполного результата. Неиспользуемый общий источник не требуется, когда явное
назначение всего vault его перекрывает.

У файла один победивший источник; отсутствующий файл не подхватывается другим
провайдером. Для смены владельца того же конечного пути нужно изменить назначение.
Это меняет namespace маршрутов и требует новой исходной версии для безопасного
обновления. Фильтрованная привязка потребляет своё удалённое поддерево: соседние
файлы вне фильтра не появляются повторно под исходным путём через общий источник
и не становятся кандидатами на удаление локальных файлов по этому пути.

## План, исполнение и результат

Ручной запуск сразу открывает одну панель состояния. Подготовку можно отменить,
включая ожидание проверки менеджера доступа. Повторный клик по статусу не создаёт
вторую панель. После получения снимков появляется единое подтверждение конкретного
плана для обычного запуска, force, retry и восстановления отсутствующих файлов.

Таблица плана содержит действие, имя подключения, исходный путь источника,
конечный путь vault и причину. Есть поиск и страницы по 100 операций.
Обновление по подтверждённой исходной версии обозначено условным действием
«Проверить и обновить»: факт замены определяется после получения и проверки байтов.
Заблокированные и отложенные удаления показываются отдельно.

В результатах различаются полученные из источника файлы, принятые версии,
фактические изменения существующих основных файлов, пропуски, конфликты и ошибки.
Плановое количество обновлений не используется как счётчик совершённых обновлений.
Входящая конфликтная копия не считается заменой основного файла.
Журнал хранит до 500 подробных результатов сессии; общий размер списка указывается,
если он усечён. Старые записи без новых полей читаются совместимо.

Блокировка до запуска имеет причину и отдельную запись попытки с нулевыми
операционными счётчиками. Есть повтор запуска с новой проверкой доступа.
Частичное исполнение, ожидание решения и отложенные удаления имеют отдельные
подписи. Retry относится к пригодным для повтора записям текущей очереди,
а не к историческому числу ошибок.

Закрытие диалога конфликта оставляет файл на месте и решение незавершённым.
Явные действия: принять источник с локальной копией; оставить локальный файл
с входящей копией; пропустить; решить позднее. Диалог статуса доступа
информационный; скрытый жест, включавший мягкий режим, удалён.

## Восстановление

Окно восстановления доступно из настроек, панели состояния, рабочего окна и команды.
Оно показывает сохранённые версии и незавершённые операции с датой, путями, размером,
статусом и занятым объёмом хранилища. Действия:

- проверить контрольную сумму копии;
- скачать проверенную версию, в том числе при исчерпанной квоте;
- создать отдельный файл рядом, не заменяя текущий;
- после проверки наблюдаемых версий оставить текущие файлы и закрыть зависшую операцию.

Восстановленный файл получает защищённое имя `.conflict-restored-<UUID>` и не участвует
в будущей синхронизации. Имя ограничено 255 UTF-8 байтами. Создание использует
неперезаписывающий API vault. История и исходная копия сохраняются.
Перед завершением зависшей операции текущие байты проверяются снова: изменение
после просмотра отклоняет решение. Эти локальные действия не требуют доступа к сети.

## Миграция и границы

Источник из старого профиля материализуется в назначениях до удаления этого поля
из профиля. Старая настройка `workspaceSync=false` один раз становится реальными
исключениями. Ошибка сохранения возвращает прежние настройки.
Изменение только участия папок не меняет namespace маршрутов и не сбрасывает исходные версии. Старый namespace, включавший немаршрутные правила папок, может смениться один раз: его кэш сохраняется отдельно и не присваивает новым маршрутам владение файлами. Новые поля области не изменяют формат журнала намерений и recovery-объектов.

Этот этап не реализует отправку локальных изменений, атомарное обновление пакета
плагина, восстановление несохранённого редакторского буфера, автоматическую очистку
recovery или ремонт повреждённого журнала. При недоступной истории окно показывает
ошибку; автоматического сброса нет. Фоновые удаления остаются отложенными;
Яндекс.Диск, Drive и WebDAV не подтверждают полноту снимка для удаления.
В общем запуске недостаточная гарантия одного участвующего источника блокирует удаления.

Стили имеют один источник в `src/ui/styles.ts` и `sync-workspace-styles.ts`.
Build и dev watcher генерируют `styles.css` из этих экспортов.
Готовый установочный пакет требует отсутствующего в исходной ветке `manifest.json`.

## Проверка

`npm run verify` запускает все 13 тестовых файлов, строгую проверку TypeScript,
генерацию стилей и production-сборку. Новый `tests/ui-overhaul.test.ts` покрывает
26 сценариев состояния, DOM, маршрутов, отмены, конфликтов и восстановления.
Регрессии проверяют A → B, фильтрованные привязки, старые перенаправления,
сохранение селекторов и защиту от устаревших форм.

Браузерная проверка использует реальные компоненты с подменённым Obsidian host
и искусственными снимками источников. Проверены широкое окно, 425×920 и 375×667,
клавиатура, доступность нижних действий, отсутствие перекрытия инспектора и
горизонтального переполнения документа. Это не проверка внутри настоящего Obsidian
и не интеграционная проверка с облачными аккаунтами.
