# Повторы, сохранение состояния и режимы записи

Сборка: `overhaul-retry-recovery-2026-10-12`.

## Ошибки и восстановление

Manifest-кэш публикуется без rename поверх существующего файла: проверенный
временный файл → предыдущая публикация сохраняется в `.previous` → новая
публикация перемещается на свободное имя. Загрузка после прерывания использует
валидную текущую либо предыдущую публикацию, но не непроверенный `.tmp`.
Операционный журнал остаётся источником подтверждённых изменений и восстановления;
это не гарантия fsync при отключении питания. Ошибка checkpoint завершает сессию
как ошибочную, не записывая уже применённый файл в очередь неудачных скачиваний.
Новые записи блокируются после обнаружения сбоя; уже начатые операции сверяются
с журналом при следующей сессии.

Журнал различает download, verify, prepare-directory, apply и checkpoint.
Таймаут отдельно указывает headers/body и длительность. Отмена пользователем
не расходует попытки и не становится сетевой ошибкой. Ошибки целостности и записи
не исправляются слепым повторным перезаписыванием файла.

Временные сетевые сбои, HTTP 408/429/5xx после быстрых сетевых попыток переходят
в сохранённую очередь: 1, 5, 15, 60 минут, далее 6 часов, плюс 0–20% случайной
задержки. Retry-After задаёт нижнюю границу; поддерживаются секунды и HTTP-date.
Такие ошибки не паркуются навсегда из-за исчерпания счётчика. Другие ошибки
файловой операции требуют внимания и не повторяются автоматически. Старые записи
очереди сохраняют свою прежнюю задержку/статус до следующей попытки.

Это время готовности к повтору, не отдельный таймер: попытка происходит при
следующем разрешённом auto-тике. При auto=off запусков нет; startup-only выполняет
один запуск. Обычная auto-сессия уже включает созревшие ошибки, поэтому второй
одновременный retry не запускается. Она не открывает ручные диалоги. Кнопка
«Повторить неудачные загрузки» после подтверждения может повторить и заблокированные
файлы, с новым манифестом/планом и всеми правилами защиты; Force Resync не нужен.

Для Yandex ограничены параллельные загрузки до двух (включая составной источник),
пауза rate-limit общая для запросов экземпляра источника. HTTP 403/404 временной
ссылки по-прежнему приводит к получению новой ссылки один раз. Внутренние быстрые
попытки скачивания остаются ограниченными тремя; внешний отложенный повтор получает
новую сессию и новый список. Указанные отсрочки относятся к пофайловым ошибкам:
сбой получения всего манифеста завершает сессию и повторяется обычным auto-тиком.

## Режимы перезаписи

| Режим | Нет локального файла | Ранее применённый файл без правок | Локальные правки / неизвестный существующий файл |
| --- | --- | --- | --- |
| Не трогать (`preserve`) | Не создавать | Не изменять | Не изменять |
| Добавлять отсутствующие (`create`) | Создать | Сохранить | Сохранить |
| Обновлять без локальных правок (`update`) | Создать | Обновить | Сохранить |
| Версия источника (`remote`) | Создать | Обновить | Применить источник, сохранить локальную конфликт-копию и предусмотренное журналом восстановление |
| Обновлять с разрешением конфликтов (`changes`) | Создать | Обновить | Использовать стратегию конфликта |

У changes доступны: локальная версия, удалённая версия с локальной копией,
входящая удалённая копия при сохранении локального файла, запрос решения.
В auto запрос решения откладывается. Одинаковые байты не требуют перезаписи;
неизвестный файл не считается безопасно обновляемым только по совпадению имени.

Удаления — отдельная настройка keep/tracked/mirror. Preserve защищает и от удаления;
фоновые удаления откладываются, Yandex не даёт подтверждённого неизменяемого снимка
для разрешения удаления. Исключения, запрет кода плагинов, проверка хэша, проверка
локальной версии и recovery действуют также при ручном retry и Force Resync.

Для обновления кода плагинов с сохранением настроек назначайте remote либо update
для main.js, manifest.json, styles.css; data.json отдельно preserve. Файлы
наподобие data.json.backup2 требуют отдельного исключения/правила — выбор data.json
не является маской для всех его резервных копий.

Проверено тестами с имитацией Obsidian/HTTP: отказ rename-overwrite, прерывания
публикации, checkpoint после записи, таймауты/отмена, rate-limit и 40 комбинаций
режим × локальное состояние × manual/auto. Реальные Obsidian и Yandex не проверены.
