# UI: jobs, дерево, планы и решения

Нормативная часть [Overhaul vNext](README.md). UI обязан объяснять реальное действие, owner и blockers; interface labels не подменяют capabilities.

## 1. Рабочее окно

Сохраняется текущая композиция из списка подключений, дерева и инспектора. Карточка подключения становится карточкой его job; дополнительные повторяющие schedule/scope настройки не вводятся. Главные views: «Vault», «Источник: <имя>», «План», «Требуют внимания», «История». В мобильной/узкой раскладке те же panes последовательно доступны tabs, не отдельные урезанные semantics.

```text
Подключения                 Файлы / план                   Инспектор
Drive Notes ↔               Vault | Источник | План        Выбранный объект
  При запуске · ожидание     Поиск · фильтр job/status      Локальный путь
  12 завершено · 1 решение   ▸ Notes [Drive, ↔]             Источник / folder ID
Git Config →                ▸ .obsidian [смешано]          Участие и профиль
  Каждые 30 мин · готово     report.md [нужен выбор]        Наследование / guards
ZIP Archive →               report.md [ID …7b2]            Разрешённые действия
  Только вручную            report.md [ID …9fa]            Preview последствий
```

Имя подключения, тип, direction summary, scope summary, schedule input/resolved, last result, progress и attention count видимы отдельно. Смешанный pull/bidirectional job показывает «смешанные профили» с scopes в inspector. `auto off` отображается «Только вручную», `enabled false` — «Подключение отключено». Auth-required, cooldown, paused и startup-completed не изображаются как off.

Card actions: preview/run, cancel current run, retry due/selected errors, open inbox, refresh contents, configure, pause/resume auto, enable/disable, account actions и remove connection. Enabled определяется по job capability/state, не по общему singleton `isRunning()`. Independent Git может запускаться при Drive waiting/failed; same-job повторный клик открывает current run, не запускает второй.

«Все подключения» — batch selected eligible jobs; итог отображает каждое отдельно. Missing/unassigned scope не автоматически становится новым default. «Сделать источником по умолчанию» редактирует draft с ownership diff, не переключает sync немедленно.

## 2. Tree identity и state

```ts
type TreeRowKey = string; // opaque, не display path
interface TreeRow {
  key: TreeRowKey; parentKey?: TreeRowKey; label: string;
  side: 'local' | 'remote' | 'projection'; kind: string;
  objectId?: string; connectionId?: ConnectionId; jobId?: JobId;
  localPath?: string; remoteDisplayPath?: string;
  policy: EffectivePolicy; evidence: 'verified' | 'observed' | 'stale' | 'unknown';
  state: RowState; plannedItemIds: readonly string[];
}
```

Local keys используют vault identity + physical normalized path + kind; remote keys — namespace/object ID/parent edge. Projection keys включают binding и remote object ID. Слияние local/remote строк выполняется по verified binding, не одинаковому имени. Несколько remote объектов на одну local цель показываются как collision group, а не один `origin: both` node.

Expanded, focused, selected и multi-selection хранят row keys per job/pair/view. При folder rename сохраняется раскрытие по ID; при root/account replacement старые keys не применяются к новому source. Row context menu получает object ID, а не повторно ищет первый path match.

Browse tree не вызывает strict executable manifest validator. Unknown names/type/path остаются отдельными rows с diagnostic. Stale snapshot после failed refresh сохраняет возраст, old root identity и reason; apply по нему disabled. Page/cursor errors не переводят source в «пустой».

Legacy local tree-walk сохраняется для folder inference и explicit empty folders. Remote builder заменяется ID graph; `Map<path,node>` не используется для raw Drive. Folder-file одинакового имени — разные rows. Cycles, repeated edges и recursion depth bounds обрабатываются без зависания; cycle diagnostic не прячется как duplicate name.

Rows показывают participation, source/job, direction, planned action/attention. «Совпадает» допускается при verified content/baseline evidence, а просто cache-hash match без local verification обозначается «По последнему снимку». На папке mixed badge вычисляется по symbolic descendants/overrides и known inventory; synthetic witness не выдаётся за uniform subtree.

Для больших деревьев — bounded/virtualized visible rows с текущим default 150 на страницу, lazy expansion и cancellable search; search не делает новые sync effects. Index по IDs/parents/local keys, без полного повторного merge на каждый keystroke. Точное требование скорости задаётся benchmark host, не произвольным обещанием «мгновенно».

## 3. Inspector и редактирование

Inspector показывает: display name, actual provider ID/parent, remote path, final local target, winning source/profile/scope rules, inherited axes, direction, observed versions/age, capabilities, pending/review связи и planned action. Полные IDs доступны в details/copy diagnostics, не загромождают каждую обычную строку.

Редактируемые блоки: участие, source binding/local destination, profile. Scope presets «весь vault / конфигурация Obsidian / выборочно» меняют одну scope tree. Profile assignment вне scope требует видимого explicit include в том же draft; preserve не превращает exclude в participation. Naming filters показываются как exact basenames и их subtree reach.

Remote duplicate row позволяет выбрать конкретный ID anchor, назначить уникальную local destination или исключить именно этот ID. «Переименовать локально» меняет mapping, не remote file. Автоматического переименования/удаления Drive duplicates нет. Если binding не может быть invertible, bidirectional preview blocked с witness и вариантами исправления.

Bulk checkbox — выделение для редактирования, не include и не sync permission. Bulk assignment показывает mixed исходные значения, сохраняет source/names/remote anchors, применяет только выбранные поля. Нельзя массовым profile change незаметно перезаписать исключения или другие scopes.

Draft сохраняет contexts при переключении views. «Сохранить» валидирует всю policy/ownership, показывает affected jobs/transfer blockers, выполняет acknowledged activation. Неизменяемые runs могут закончить старый plan, если новые drafts ещё не activated; activation fences affected writers. Failure/timeout показывает конкретную фазу, draft не теряется и UI не остаётся в вечном saving.

## 4. Preview и выполнение

Preview выбирает jobs, показывает этап наблюдения/ошибки каждого и допускает independent ready plans. Таблица содержит job, action/direction, original remote locator, local destination, reason, bytes, guards, dependencies и effect status. Upload-new, proposal-copy, remote trash, local trash, download, unknown, no-op и unsupported различимы.

Фильтры: job, действие, status, search; текущий default 100 операций на страницу. Counts считаются по plan items и settled intents, не выводятся из страницы или повторно appended rows. «Обновления» означает actual canonical replacements, а uploaded proposal — отдельный counter.

Manual apply использует exact plan/consent версии. При stale policy/bytes/remote version affected items replan, и изменившийся destructive choice подтверждается заново. Running activity подписана на job events. Closing progress UI не cancel; кнопка cancel явно останавливает новые effects и показывает pending recovery для неизвестного результата.

Retry строит свежий targeted plan для выбранных queue IDs; `restore missing` не загружает local-only файлы в Drive и не переносит удаления; `force reconcile` заново наблюдает состояния, не стирает baseline/pending/reviews и не снимает protections. Legacy «force resync» не является кнопкой сброса Drive identity.

Manual conflict dialog открывается после независимых effects. Закрытие оставляет inbox entry. Background не открывает modal; attention count и link видимы. Ошибка одного dialog/action остаётся в его row, не завершает все other jobs как failed.

## 5. Inbox конфликтов и неизвестности

Inbox accessible из job card, global status, workspace, settings и command. Группировка job → logical file → entries/proposals. Entry содержит исходные версии, обе canonical стороны, сохранённые copies, reason, freshness и allowed actions. Новое proposal не вытесняет прежнее.

| Entry | UI действия |
|---|---|
| Ask conflict | Preview обеих версий; принять разрешённый winner с copy, оставить pending; disabled unsupported choices |
| Gated local update | Открыть local/Drive proposal и original; refresh, acknowledge retained proposal, explicit restore/отказ с preview |
| Delete/edit | Показать сторону deletion, evidence и saved edit; сохранить/восстановить разрешённую версию, отложить |
| Unknown 404/access | Проверить доступ, reauthorize, rebind verified object, publish-new/detach через guarded resolution |
| Collision | Показать обе IDs/parents/names и final target; ID mapping/exclude; независимые rows доступны |
| Recovery unknown | Probe/verify, экспорт redacted diagnostics, guarded operator actions; никакого безусловного «закрыть» |
| Relocation | Actual object location, old binding; принять новый mapping либо оставить detached tracking с receipt |

«Оставить текущий» различает keep current version и доказанный settle pending operation. Нельзя удалять recovery lease без evidence только ради чистого списка. «Решено» не означает canonical convergence; acknowledged proposal может остаться divergent и это видно в row/history.

Artifact rows на peer vault видимы и доступны в inbox origin file. Они не помечаются глобальным «никогда не синхронизируется» по `.conflict-*`. Legacy backup/conflict-restored остаётся отдельной защищённой версией, пока пользователь не выбрал explicit import; восстановление из recovery не включает файл в sync случайно.

## 6. Статус, popover и public hook

Statusbar показывает active jobs/attention/errors с кратким label, например «Синхронизация: 1 · требуют решения: 2». В idle — результат последней accounted работы, а не глобальный флаг на все providers. Global authority/storage fatal имеет отдельный marker; failed Drive и successful Git сохраняют оба исхода.

Popover список jobs показывает configured/resolved schedule, current run, next periodic/retry/finishing, pause/blocked reason и last attempt/completion/convergence. «При запуске · стартовый проход завершён» отображается при `nextPeriodicAt=null`; auto-off выводится только из configured/resolved off. Pause all — явная batch action, individual pause — на card.

Journal содержит batch/job grouping, direction-aware counters, proposal/decision/unknown outcomes и ссылки в recovery/inbox. Старые rows без job identity не переписываются на текущие names. Last sync success label не основывается на timestamp неудачной попытки.

`window.vaultSync` сохраняет compatible aggregate read-only fields и optional versioned jobs projection. Consumer не видит секреты; подписчик exception не ломает pipeline. UI не делает отдельное вычисление schedule semantics по одному выбранному Scheduler.

## 7. Picker, connection/account settings и recovery

Folder picker сохраняет breadcrumb/current/history **после** successful navigation. Failed Back/Forward остаётся на исходной папке; повтор/cancel доступны. Cancellable request stamped account/root/request ID. Поддержанные Drive folder links разбираются строго; document URL не объявляется папкой. Duplicate folder names отображаются по разным IDs.

OAuth/client import: повтор того же client config idempotent; другой client явно требует grant invalidation/reauthorization. Pick root не меняет grant, а account change не сохраняет чужой token. Login modal bounded stages/cancel сохраняются; отсутствие browser callback не бесконечное «ожидание».

Connection settings проверяют list/read и write/trash capabilities раздельно, не обещают bidirectional по успешному list. Test connection не начинает upload пользовательского файла. Любой live mutation test — отдельный явно ограниченный test fixture и действие, не скрытая часть browse.

Recovery view фильтруется по job/generation и показывает old/unknown domains, intent/effect evidence, blob verification и retained bytes. Локальный export/create-sibling доступен без cloud, но закрытие remote unknown требует probe/accounting. «Очистить безопасный мусор» показывает verified candidates и retention reasons; clear journal не clear state.

Remove/disable connection показывает difference: остановить job, сохранить files и ownership; remove требует reassign/detach scope и удерживает pending history. Account revoke перечисляет jobs, которые потеряют доступ. Recovery refs/доступные artifact copies не удаляются автоматически вместе с card.

## 8. Доступность и UI проверки

Tree roles/aria-level/expanded/selected основаны на row key. Стрелки, Home/End, Enter inspector и Space multi-select сохраняются; expander/checkbox не double-trigger selection. Фокус удерживается при updates, virtualization и совпадающих labels; поиск/ошибки имеют accessible labels, status `aria-live` throttled без потока notices.

RU/EN строки добавляются через i18n; raw stack/API reason остаётся details с безопасным текстом. Desktop-only OAuth/bidir host restrictions видимы до попытки запуска. Закрытие modal снимает subscriptions и aborts только owned browse/draft requests, не соседние running jobs.

UI contract tests проходят через настоящую PathPolicy/BindingCompiler/event projections, не тестовую фикстуру с исключением `.conflict-*`. Все callbacks получают IDs; tree выбор второго одинакового имени обязан действовать на второй object, включая после refresh и смены sorting.
