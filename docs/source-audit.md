# Проверка источников после перехода на подключения

Проверены форма подключения, schema реестра, минимальная конфигурация,
маршрутизация плагина, получение списка и скачивание файлов.

| Источник | Подтверждённый дефект | Исправление |
| --- | --- | --- |
| GitHub | `default` отправлялся как буквальное имя ветки; `all` обещал объединение веток | Пустое поле / `default` разрешается через `default_branch` репозитория. `all` отклоняется с пояснением; задаётся одна ветка |
| GitHub | URL другого Git-хоста без API-корня мог читать одноимённый репозиторий GitHub | Адрес отклоняется до сети. Форма указывает GitHub/GitHub Enterprise; Gitea/GitLab не заявлены как совместимые |
| Drive | API key без folderId обещал весь личный диск | Требуется ID публичной папки; `root` и пустое поле не допускаются к запросам |
| Drive | Переключатель Google Docs не выполнял экспорт | Переключатель убран; подсказка явно перечисляет пропускаемые документы и ярлыки. Старый includeDocs не включает экспорт |
| WebDAV | Публичный сервер требовал фиктивное имя пользователя | Имя и пароль можно оставить пустыми; Authorization не отправляется. Пароль без имени отклоняется |
| ZIP | Nextcloud с query получал `/download` в параметре вместо пути | Меняется pathname, параметры сохраняются |
| ZIP | Современные Dropbox `/scl/fi` и `/scl/fo` не получали `dl=1` | Добавлено распознавание с сохранением rlkey и других параметров |
| Формы | Описания полей schema не отображались | Подсказки показываются в обоих редакторах подключения |

Общее исправление выбора источника из предыдущего изменения действует на все
провайдеры: «Подключения → Источник для хранилища», либо отдельное назначение в
дереве. Создание подключения не переназначает файлы автоматически. Отсутствующий
или недоступный обязательный источник останавливает сессию до записи.

## Проверки и границы

Регрессии используют настоящие классы источников и маршрутизацию main.ts с
имитацией HTTP/ZIP: каждый выбранный провайдер выдаёт список и байты файла.
Отдельно проверяются default/явная ветка, запрет all, чужой Git-хост, Drive без
папки, анонимный WebDAV и преобразование общих ссылок. Общий набор проверяет
права на пути, неполные списки, коллизии и восстановление.

Реальные аккаунты и Obsidian desktop/mobile не проверялись. OAuth Drive,
экспорт Google Docs и API Gitea/GitLab не реализованы. Произвольные страницы
шаринга ZIP, страницы подтверждения Google Drive, Nextcloud в нестандартном
подпути и защищённые паролем ссылки требуют отдельной проверки/поддержки.
HEAD/Range-проверка ZIP и валидация Content-Range остаются отдельными пунктами
аудита. Git symlink/submodule semantics также не закрыты этой проверкой.
