# Sync

Плагин Obsidian для загрузки файлов из Git, ZIP, Яндекс.Диска, Google Drive и WebDAV в локальный vault. Направление синхронизации сейчас — **из источника в vault**. Локальные изменения не отправляются обратно.

Идёт поэтапный overhaul. После защиты существующего pipeline добавлены неизменяемый план, журнал намерений, recovery-объекты и сверка операций после сбоя. Этап 2б.1 заменил перезапись всего журнала небольшими checksum-записями и адаптивными checkpoints с компактацией. Режимы перенесены в профили с назначениями из дерева и выбором источника для каждого файла. Изменения поведения и следующие этапы описаны в [docs/overhaul.md](docs/overhaul.md).

## Среда разработки

Нужны Node.js 22+ и npm. Зависимости закреплены в `package-lock.json`.

```sh
npm ci
npm run verify
```

`verify` запускает строгую проверку TypeScript, регрессионные тесты и сборку. Команды доступны отдельно: `npm run typecheck`, `npm test`, `npm run build`. Тесты не используют облачные аккаунты или пользовательские vault: основные порты подменяются, публикация и компактация журнала также проверяются в настоящем временном каталоге файловой системы.

`npm run bench:state` измеряет объём записи метаданных и время на 100, 500 и 5000 новых файлов, с applied-эффектами и без них. Benchmark использует in-memory порты; он не измеряет скорость настоящего диска, Obsidian или сети.

Сборка создаёт `dist/main.js` и карту исходников. Библиотека XML входит в bundle, API `obsidian` предоставляется приложением. В этом checkout отсутствует `manifest.json`: готовый установочный пакет не создаётся. Идентификатор плагина и метаданные существующего релиза нельзя заменять выдуманными значениями; их нужно восстановить до выпуска.

## Текущие ограничения

- Фоновые удаления отложены до реализации явных разрешений.
- Удаления для Drive, Яндекс.Диска и WebDAV заблокированы: их текущий обход не доказывает полноту снимка. Обновления файлов продолжают работать по существующим правилам.
- Ручное удаление из Git/ZIP и замена конфликтующей локальной версии требуют восстановительной копии. Копии `.conflict-*` создаются рядом с исходным файлом и автоматически не удаляются.
- Изменение локальных байтов или настроек после preview блокирует устаревшую операцию. Full проверяет локальное содержимое также при неизменившейся удалённой версии.
- Журнал и скрытое recovery-хранилище находятся в директории плагина. Повреждённое состояние, разрыв цепочки записей или неизвестная версия после сбоя останавливают исполнение; интерфейс разрешения таких случаев ещё не реализован. Лимиты: 512 MiB recovery-объектов и 10 000 записей операций. Компактация сокращает файлы журнала, сохраняя полную историю; retention и освобождение квоты ещё не реализованы.
- Пустые папки автоматически не удаляются.
- Проверки в настоящем Obsidian, на мобильном устройстве и с реальными аккаунтами остаются отдельным этапом. Проходящие тесты ядра не подтверждают готовность production-релиза.

## File write and deletion rules

Settings provides standard/custom sync profiles and named source connections. Assign profiles in the file tree to the vault, folders or individual files, with plugin code/settings quick selections. Each file uses one source; ambiguous assignments block synchronization. See [the profile guide](docs/file-rules.md) for migration, precedence, multi-provider examples and limits. Script permissions and scheduling remain off by default.
